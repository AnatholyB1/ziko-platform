## v1.5 Requirements (All Marked as Delivered or Deferred)

### Coach Identity & Onboarding (COACH)

- [x] **COACH-01**: A user can become a coach via a self-serve signup flow on `ziko-app.com/coach/onboarding` and have their `user_profiles.role` promoted to `coach` or `both` without admin intervention. *(Phase 24 — 24-04 promoteRole Server Action + onboarding wizard)*
- [x] **COACH-02**: A coach can fill in their public profile (display name, bio, specialties, optional website) and see it persisted in `coach_profiles`. *(Phase 24 — 24-04 saveProfile Server Action)*
- [x] **COACH-03**: A coach can submit optional KYC data (certifications, ID document upload) without blocking access to coach features; KYC status remains `pending` until reviewed. *(Phase 24 — 24-04 saveKyc + coach-kyc bucket migration 037)*
- [x] **COACH-04**: A user who is both client and coach (`role='both'`) can access both the athlete app and the coach web CRM with the same account. *(Phase 24 — promoteRole supports `both` + CoachSidebar layout independent of mobile)*
- [x] **COACH-05**: A coach can edit their profile, specialties, and KYC documents from `/coach/settings`. *(Phase 24 — settings page with edit forms)*

### Invitations & Coach↔Client Linking (INVITE)

- [x] **INVITE-01**: A coach can generate a unique 6-character invitation code (format `[A-Z2-9]{6}`) from their dashboard, set its expiration (default 14 days), and copy/share it. *(Phase 25 — 25-02 generate route + InvitationCodeCard)*
- [x] **INVITE-02**: A coach can see all their issued invitations with status (active / used / expired / revoked) and revoke any active invitation. *(Phase 25 — 25-04 InvitationsTable + revoke Server Action)*
- [x] **INVITE-03**: An athlete can enter a coach invitation code from the mobile app and have a `coach_client_links` row created with `status='active'`. *(Phase 25 — /redeem web state machine — note: mobile entry via web page, not native screen)*
- [x] **INVITE-04**: Invitation code redemption is rate-limited (5 attempts / 15min per IP, 10 attempts / hour per user) and returns constant-time responses regardless of failure reason. *(Phase 25 — 25-03 composed Upstash sliding window + constant-time INVALID_OR_EXPIRED envelope)*
- [x] **INVITE-05**: An athlete sees a coach profile preview (display name, bio, specialties, photo) before confirming the link. *(Phase 25 — 25-05 CoachPreviewCard on /redeem state B)*
- [x] **INVITE-06**: An athlete can revoke an active coach link from their mobile settings in a 2-step confirmation; coach loses read access immediately. *(Phase 25 — typed "COACH" confirmation RevokeConfirmModal + DELETE /clients/links/me route)*
- [x] **INVITE-07**: An expired or already-used invitation code returns a clear error and cannot create a link. *(Phase 25 — 25-03 constant-time error, peek_invitation RPC, migration 040)*

### CRM Client Management (CLIENT)

- [x] **CLIENT-01**: A coach can see a paginated list of all linked clients on `/coach/clients` with name, photo, last-active timestamp, and quick filters. *(Phase 26 — 26-04 ClientsTable + TanStack Table)*
- [x] **CLIENT-02**: A coach can search clients by name and apply roster filters by signal (missed last 2 sessions / measurements not updated >4 weeks / mood declining). *(Phase 26 — 26-04 signal chips + search input)*
- [x] **CLIENT-03**: A coach can open a client detail page at `/coach/clients/[id]` showing tabs for sessions, measurements, habits, nutrition, sleep, cardio, journal — all read-only. *(Phase 26 — 26-05 7-tab client detail layout)*
- [x] **CLIENT-04**: A coach sees an "executive summary" card at the top of the client detail (% weekly compliance, last workout date, latest measurement, mood trend over 14 days). *(Phase 26 — 26-06 ExecutiveSummaryCard)*
- [x] **CLIENT-05**: A coach can attach custom text tags to a client via a `coach_client_tags` table; tags are coach-private. *(Phase 26 — 26-06 ClientTagInput + migration 041)*
- [x] **CLIENT-06**: A coach can write private notes per client in a dedicated editor (`coach_client_notes` table); notes are coach-private and version-tracked. *(Phase 26 — 26-06 ClientNotesPanel + migration 041)*
- [x] **CLIENT-07**: A coach can select 3-5 linked clients and view a multi-client comparison chart for any common metric. *(Phase 26 — 26-07 ComparisonChart + compare page)*
- [x] **CLIENT-08**: A coach can revoke a coach↔client link from their dashboard with a 2-step confirmation; client retains all data but coach loses read access. *(Phase 26 — 26-02 DELETE /links/:clientId + revoke confirmation)*

### Coaching Programs (PROG)

- [x] **PROG-01**: A coach can create a workout program template at `/coach/programs/new` with metadata persisted as `workout_programs` with `is_template=TRUE` and `created_by_coach_id` set. *(Phase 27 — 27-06 new program form)*
- [x] **PROG-02**: A coach can structure a program as multi-week with multiple sessions per week, each session containing exercises with sets, reps, target RPE/RIR, rest interval; persisted in `weeks_data` JSONB. *(Phase 27 — 27-07 WeekAccordion + SessionSlideOver + program editor)*
- [x] **PROG-03**: A coach can pick exercises from the existing Ziko exercise library (1000+ entries) or add free-text exercise names. *(Phase 27 — 27-07 ExerciseTypeahead debounced fetch)*
- [x] **PROG-04**: A coach can organize templates into folders. *(Phase 27 — 27-06 folder structure on list page)*
- [x] **PROG-05**: A coach can duplicate a template via context-menu. *(Phase 27 — 27-06 duplicate action)*
- [x] **PROG-06**: A coach can assign a template to one or more linked clients; assignment creates a forked copy with `is_template=FALSE`. *(Phase 27 — 27-07 AssignmentModal + backend fork-on-assign)*
- [x] **PROG-07**: A coach can edit an assigned program without modifying the source template. *(Phase 27 — fork semantics via `template_source_id` back-reference)*
- [x] **PROG-08**: Ziko ships with 5–10 expert-curated seed templates available to every coach on signup. *(Phase 27 — 27-03 migration 046 seed templates)*
- [ ] **PROG-09**: A client can see their assigned program in the mobile app under "Mon coach" and execute its sessions. *(Phase 27 Track B — 3 gaps deferred to Phase 41 in milestone-mobile; MOBILE-02/03/04/06 partial)*

### AI File Imports (IMPORT)

- [x] **IMPORT-01**: An authenticated user can upload a workout file (PDF, image, Excel, Word) up to 25 MB via drag-drop; sent directly to Supabase Storage via signed URL. *(Phase 28 — 28-04/28-06)*
- [x] **IMPORT-02**: After upload, parse step runs Claude vision/document parsing returning `ImportedProgramSchema` Zod-validated; credits deducted only on success. *(Phase 28 — 28-02 parse submodule)*
- [x] **IMPORT-03**: Preview UI shows extracted program with confidence scores; fields <70% highlighted yellow. *(Phase 28 — 28-06 preview/editor page)*
- [x] **IMPORT-04**: User can edit any field in preview before committing. *(Phase 28 — 28-06 editable fields)*
- [x] **IMPORT-05**: Athlete can import in "athlete mode" — committed program owned by them. *(Phase 28 — 28-04 athlete mode)*
- [x] **IMPORT-06**: Coach can import in "coach template mode" — `is_template=TRUE`. *(Phase 28 — 28-04 coach mode)*
- [x] **IMPORT-07**: Multi-page PDF programs (up to 30 pages) extracted page-by-page and reassembled. *(Phase 28 — 28-02 unpdf multi-page)*
- [x] **IMPORT-08**: Re-upload new version shows diff before committing. *(Phase 28 — 28-04 diff view)*
- [x] **IMPORT-09**: Import flow is async — client polls every 2s, handles up to 60s parse. *(Phase 28 — 28-04 polling + status route)*
- [x] **IMPORT-10**: Failed imports display clear error and do not deduct credits. *(Phase 28 — 28-02 credits deducted only on success)*
