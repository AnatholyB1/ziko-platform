## 5. Gap Detail: AI-04 ChartCard Badge

**Description:** Coach should see an orange or red pill badge in each ChartCard title bar when a client's metric crosses a configured threshold. This provides at-a-glance alerting without opening the Alertes modal.

**Root cause:** Plan 05 Task 2 correctly wired `chartInsights` threading from page → sport dashboards → ChartCard but did not add the parallel `crossedThresholds` threading. Plan 05 Task 3 (page wiring) passed `crossedThresholds` only to `AlertesModal`, not to sport dashboards.

**What works:** AlertesModal correctly displays orange dots for crossed thresholds. Threshold CRUD (create/delete via AlertesModal) works. Threshold evaluation happens in the insights backend.

**What does not work:** The `ChartCard` badge (`metricKey` + `crossedThresholds` props) is never received by any ChartCard instance. The `alertBadge` condition is permanently false.

**Fix scope (3 changes per sport dashboard × 5 + page.tsx):**

```tsx
// In page.tsx — add crossedThresholds to sport dashboard props (same line as chartInsights):
<PowerliftingDashboard
  clientId={clientId}
  sport={sport}
  dateRange={dateRange}
  onDataReady={handleDataReady}
  chartInsights={insights?.chartInsights}
  crossedThresholds={insights?.crossedThresholds}  // ADD
/>

// In each sport dashboard interface:
interface Props {
  // ... existing props
  crossedThresholds?: ThresholdAlert[]  // ADD
}

// In each sport dashboard ChartCard call (CHART_CARDS map):
<ChartCard
  title={card.title}
  aiInsight={chartInsights?.[card.chartKey]}
  metricKey={card.chartKey}         // ADD
  crossedThresholds={crossedThresholds}  // ADD
>
```

**Risk:** Low. All new props are optional. No existing behavior changes. The badge is additive UI.
