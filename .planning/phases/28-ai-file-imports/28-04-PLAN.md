    Route registration order (CRITICAL — pitfall 4 static-before-dynamic):
    1. GET /           → listImports
    2. POST /          → createImport (returns import_id + signed_upload_url)
    3. PUT /:id/status → updateStatus (pending → uploaded)
    4. POST /:id/parse → triggerParse (returns 202; async parse in background)
    5. GET /:id        → getImport (poll status)
    6. PUT /:id/commit → commitImport

    Static paths (/, /status, /parse, /commit suffixes) are matched BEFORE /:id.

    POST /:id/parse handler (async parse logic):
    - Returns 202 immediately BEFORE starting parse
    - Reads import row, validates status = 'uploaded'
    - Computes creditCost: mime_type === 'application/pdf' ? Math.min(page_count ?? 1, 10) : 1
    - Inline credit check using creditService.getQuotaStatus + balance check (NOT creditCheck middleware)
    - On insufficient credits: updates status = 'failed', error_message = 'insufficient_credits', returns 402
    - Sets status = 'parsing' in DB
    - Starts async parse in background (using a Promise chain, NOT await — the 202 has already been returned)
    - Background parse: download file from Supabase Storage → dispatch to pdf/excel/word/image parser → call parseWithVision or parseWithText → on success: update status='ready', parsed_data, confidence_scores, credit deducted (costOverride) → on failure: update status='failed', error_message
    - 55-second guard: use `setTimeout(() => { if (status still 'parsing') updateImportStatus(..., 'failed', { error_message: 'timeout' }) }, 55000)` registered before the async chain; clear it on resolution

    POST / handler (create import + signed URL):
    - Validates body: filename, mime_type (must be one of 6 allowed MIME types), size_bytes (> 0, ≤ 26214400), mode
    - Calls createImport to insert record with status='pending'
    - Generates signed URL: `supabase.storage.from('ai-imports').createSignedUploadUrl(${userId}/${importId}/${filename})`
    - Updates file_url in db with the storage path
    - Returns `{ import_id, signed_upload_url, path }`

    PUT /:id/status handler:
    - Accepts `{ status: 'uploaded' }` only (reject other values with 400)
    - Validates current status is 'pending' before updating (return 409 if not pending)

    PUT /:id/commit handler:
    - Reads import row, validates status = 'ready'
    - Calls commitImport with parsed_data from request body (user-edited) and mode from import row
    - Returns `{ program_id }`

    All handlers: use authMiddleware, extract userId via `c.get('auth').userId`, extract jwt via `c.req.header('Authorization')!.slice(7)`. UUID validation with UUID_REGEX before DB calls.

    Supabase admin client in service.ts: use service key (`process.env.SUPABASE_SERVICE_KEY ?? process.env.SUPABASE_PUBLISHABLE_KEY!`) to download files from storage during parse (service key needed for storage download). This is the ONLY service-key usage — all DB queries use JWT client via db.ts.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /coach/imports | Untrusted filename, mime_type, size_bytes in request body |
| client → PUT /:id/commit | Untrusted parsed_data (user-edited program) crosses trust boundary |
| service.ts → Supabase Storage | Admin client used for download only — scoped to ai-imports bucket path validation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-04-01 | Tampering | POST / mime_type validation | mitigate | Server validates mime_type against the 6 allowed values before DB insert (DB CHECK constraint is backup) |
| T-28-04-02 | Denial of Service | POST / size_bytes validation | mitigate | Server validates size_bytes ≤ 26214400 before DB insert; DB CHECK constraint is backup |
| T-28-04-03 | Spoofing | Signed URL path prefix | mitigate | Storage path `${userId}/${importId}/${filename}` ensures user cannot upload to another user's prefix |
| T-28-04-04 | Elevation of Privilege | Credit bypass via parse handler | mitigate | Credit check is server-side; creditCost computed from DB page_count (server-stored), not from client input |
| T-28-04-05 | Tampering | PUT /:id/commit parsed_data injection | mitigate | parsed_data stored as JSONB; no SQL injection vector. Downstream Zod validation in commitImport ensures shape compatibility |
| T-28-04-06 | Information Disclosure | GET /:id cross-user access | mitigate | db.getImport uses JWT-scoped client; RLS ai_imports_own enforces owner-only. 404 returned for non-owned imports |
</threat_model>
