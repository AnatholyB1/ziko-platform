<objective>
Eliminate the primary performance bottleneck: the shared coach layout re-runs three expensive queries
(getUser, user_profiles role check, coach_alerts count) on EVERY page navigation because both the layout
and each page component call createServerSupabase() independently.

Next.js App Router renders layouts and pages as separate async server components in the same request.
React's `cache()` function deduplicates identical async function calls WITHIN a single request — the
second caller gets the already-resolved promise at zero cost.

Purpose: After this plan, navigating the coach dashboard triggers ONE auth DB hit and ONE alerts count
query per request, regardless of how many server components call getCachedCoachUser().
Output: `apps/web/src/lib/coach/auth.ts` with two exported cache-wrapped helpers, consumed by the layout.
</objective>

    Import `cache` from `'react'` and `createServerSupabase` from `'@/lib/supabase/server'`.
    Import `redirect` from `'next/navigation'` and `getLocale` from `'next-intl/server'`.

    Export `getCachedCoachUser` as a React-cached async function that:
    1. Calls `createServerSupabase()` and `supabase.auth.getUser()`.
    2. If no user, calls `redirect(\`/\${await getLocale()}/login\`)`.
    3. Queries `user_profiles` for `role` where `id = user.id` (`.single()`).
    4. If `!profile || !['coach', 'both'].includes(profile.role)`, calls `redirect(\`/\${await getLocale()}/coach/onboarding\`)`.
    5. Returns `{ user, role: profile.role }`.

    Export `getCachedAlertCount` as a React-cached async function that:
    1. Calls `getCachedCoachUser()` (already cached — free second call).
    2. Calls `createServerSupabase()` and queries `coach_alerts` with `count: 'exact', head: true`,
       filtering `coach_id = user.id` and `is_read = false`.
    3. Returns `count ?? 0` as a number.

    Important notes:
    - `cache()` from React deduplicates calls within a single request. Each new request gets a fresh
      execution. This is safe for auth — no cross-request leakage.
    - Do NOT use Next.js `unstable_cache` here — that caches across requests and would break auth
      (a logged-out user could get a cached "logged in" result).
    - `createServerSupabase()` is called inside each cached function separately. That's fine — the
      Supabase client itself is cheap to construct; only the DB queries are expensive.
    - The `cache: 'no-store'` in `createServerSupabase`'s global fetch config remains untouched.
  </action>

|----------|-------------|
| React cache() scope | cache() deduplicates within a single request — NOT across requests |
| Supabase fetch layer | cache: 'no-store' prevents HTTP-level cross-user cache sharing |
