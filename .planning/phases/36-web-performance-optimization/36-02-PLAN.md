<objective>
Two changes in this plan:

1. Remove redundant `getUser()` calls from route pages that live inside the coach layout segment.
   The coach layout (plan 01) already auth-guards every request — page-level getUser() calls are
   pure duplication. Each page currently runs its own `supabase.auth.getUser()` on top of the layout's
   call. With React cache() in place (plan 01), calling `getCachedCoachUser()` in a page component is
   free (same request, cached promise). Pages that only need `user.id` for a query should import
   `getCachedCoachUser()` instead of constructing a fresh Supabase client just to call getUser().

2. Apply ISR (`export const revalidate = 60`) to the settings page, which loads the coach's own profile
   — data that changes at most once per settings-save action, not on every navigation.

Purpose: After this plan, every coach page avoids a redundant auth DB call. The settings page gets a
60-second ISR window. Client-data pages keep force-dynamic (correct — client records change live).
Output: All listed page files refactored; TypeScript clean.
</objective>
