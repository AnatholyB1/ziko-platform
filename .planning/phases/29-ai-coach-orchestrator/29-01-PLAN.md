    - `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`

    Table `public.ai_tool_audit`:
    - `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
    - `coach_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE`
    - `tool_name TEXT NOT NULL`
    - `target_client_id UUID NULL REFERENCES auth.users(id) ON DELETE SET NULL`
    - `args_hash TEXT NOT NULL`
    - `result_status TEXT NOT NULL CHECK (result_status IN ('success','error'))`
    - `conversation_id UUID NULL REFERENCES public.ai_conversations(id) ON DELETE SET NULL`
    - `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`

    RLS for `coach_alerts`:
    - `ALTER TABLE public.coach_alerts ENABLE ROW LEVEL SECURITY;`
    - Policy `"coach_alerts_own"`: `USING (auth.uid() = coach_id) WITH CHECK (auth.uid() = coach_id)`

    RLS for `ai_tool_audit`:
    - `ALTER TABLE public.ai_tool_audit ENABLE ROW LEVEL SECURITY;`
    - Policy `"ai_tool_audit_own"`: `USING (auth.uid() = coach_id) WITH CHECK (auth.uid() = coach_id)`

    Indexes (use `CREATE INDEX IF NOT EXISTS`):
    - `idx_coach_alerts_coach_unread ON public.coach_alerts(coach_id) WHERE is_read = false`
    - `idx_coach_alerts_created ON public.coach_alerts(coach_id, created_at DESC)`
    - `idx_ai_tool_audit_coach_date ON public.ai_tool_audit(coach_id, created_at DESC)`

    Note: Both tables are inserted by the cron route using the service key (no user JWT available during cron). The RLS policies cover coach reads; service-key inserts bypass RLS by design. This is the same rationale as the storage cleanup cron (Phase 15).
