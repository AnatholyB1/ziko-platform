  <action>
**Root cause investigation order:**

1. **JWT via getSession() vs getUser():** `getSession()` returns a cached session and can return `null` inside Server Actions when cookies are not forwarded correctly. Replace `getBearer()` to use `supabase.auth.getUser()` which forces a live token refresh from the Supabase Auth server. Pattern:
   ```typescript
   async function getBearer(): Promise<string | null> {
     const supabase = await createServerSupabase();
     const { data: { user } } = await supabase.auth.getUser();
     if (!user) return null;
     // getSession() after getUser() succeeds is safe — session is now refreshed in memory
     const { data } = await supabase.auth.getSession();
     return data.session?.access_token ?? null;
   }
   ```

2. **API_URL in Server Actions:** `NEXT_PUBLIC_API_URL` is available on the server too (it is env-prefixed for client exposure but also present server-side). However, if the backend is running locally at `http://localhost:3000` and the web app is at port 3001, the fetch from the Server Action hits the wrong host. Check: does `apps/web/.env` or `apps/web/.env.local` define `NEXT_PUBLIC_API_URL`? If not, the fallback `http://localhost:3000` may conflict. Add a server-only `API_URL` that falls back to the public one:
   ```typescript
   const API_URL = process.env.API_URL ?? process.env.NEXT_PUBLIC_API_URL ?? 'http://localhost:3000';
   ```
   (The server-side `API_URL` without the `NEXT_PUBLIC_` prefix is invisible to the client bundle — safe.)

3. **Error surfacing:** Currently `catch {}` silently returns `{ ok: false, error_code: 'NETWORK' }` which the UI maps to `'invalidOrExpired'`. Add `console.error` calls inside every catch block so the Vercel/Next.js server logs show the actual failure:
   ```typescript
   } catch (e) {
     console.error('[redeem/actions] previewCodeAction fetch failed:', e);
     return { ok: false, error_code: 'NETWORK' };
   }
   ```
   Apply the same to `redeemCodeAction`, `revokeLinkAction`, and `fetchActiveLinkAction`.

4. **fetchActiveLinkAction response shape:** The action currently does `return res.json()` directly. If the backend returns `{ link: null, preview: null }` (200 with link=null when unlinked), this is correct. But if `res.json()` throws (malformed JSON), it falls into the catch block silently. Wrap it:
   ```typescript
   const body = await res.json().catch(() => null);
   if (!body) return { link: null, preview: null };
   return { link: body.link ?? null, preview: body.preview ?? null };
   ```

Apply all four fixes to `apps/web/src/lib/redeem/actions.ts`. Do not change the function signatures or exported names — `RedeemStateMachine.tsx` imports them directly.
