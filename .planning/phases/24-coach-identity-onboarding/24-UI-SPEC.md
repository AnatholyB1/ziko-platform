## Spacing Scale

Declared values (multiples of 4 only). Derived from the existing web app's Tailwind v4 usage (8px grid observed in `Header.tsx`, `Hero.tsx`, `Footer.tsx`).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline label padding, chip inner gap |
| sm | 8px | Compact element spacing, button icon-to-text gap |
| md | 16px | Default element spacing, form field gap, sidebar item padding |
| lg | 24px | Card padding, section padding, wizard step padding |
| xl | 32px | Layout section gaps, sidebar width inner padding |
| 2xl | 48px | Major section breaks, wizard container vertical padding |
| 3xl | 64px | Page-level vertical spacing |

Exceptions:
- Touch / click targets minimum: 44px height (buttons, nav items, file upload buttons)
- Sidebar width: 240px fixed (design decision — matches standard CRM sidebar proportion)
- Wizard progress bar height: 4px (decorative, not a spacing token)
- KYC document row height: 48px (touch target compliance)
- Profile photo upload area: 96px × 96px (avatar size with 8px gap to text)

## Typography

Tailwind v4 utility classes. No custom font loaded — inherits system font. Exact px values for precision; use Tailwind's `text-*` scale equivalents where available.

| Role | Size | Weight | Line Height | Tailwind class |
|------|------|--------|-------------|----------------|
| Body | 16px | 400 (normal) | 1.5 | `text-base font-normal leading-relaxed` |
| Label / Small | 14px | 400 (normal) | 1.5 | `text-sm font-normal leading-relaxed` |
| Heading | 20px | 700 (bold) | 1.2 | `text-xl font-bold leading-tight` |
| Display | 28px | 900 (black) | 1.15 | `text-3xl font-black leading-none` |

Additional rules:
- Wizard step title: 20px / bold / leading-tight (Heading role)
- Sidebar nav item label: 14px / 500 (medium) — exception to 2-weight rule; Tailwind `font-medium` is already used in the existing codebase for nav items (observed in `Header.tsx`)
- Form input value: 16px / 400 / 1.5 (Body role)
- Form label: 14px / 500 / 1.4 — above each input, Tailwind `text-sm font-medium`
- Status chip / badge text: 12px / 700 / 1 — `text-xs font-bold`
- Error message: 14px / 400 / 1.4 — `text-sm text-red-600` (see Color section)

## Interaction Contracts

### Wizard State Management

Decision (from Claude's Discretion): Use **URL search params** (`?step=2`) for wizard step state.
- Rationale: resumable on browser refresh, works with browser back button, safe to expose step number.
- Implementation: `useSearchParams` + `useRouter().push` for step navigation.
- Step validation before advance: Step 1 requires auth check (redirect if unauthenticated). Step 2 requires `display_name` non-empty before enabling "Continuer".

### Form Validation

- Client-side: HTML5 `required` attribute + custom JS for URL format, max-length on specialties.
- Server-side: Zod `CoachProfileSchema` on Server Action; errors returned as `{ field, message }` map.
- Display: inline error below each field on submit attempt (not on blur for simpler UX).

### Photo Upload Flow

1. User clicks "Choisir une photo" → native file picker (accept: `image/jpeg,image/png,image/webp`, max 5 MB).
2. Client validates size + type → shows preview in 96×96 avatar circle.
3. On Step 2 form submit: request signed upload URL from backend → PUT to Supabase Storage → receive CDN URL → include in profile Server Action payload.
4. Upload failure: show `Upload.error` copy below the photo field, allow retry.

### KYC Upload Flow

Same signed URL pattern as photo. Each doc type row independently:
1. Click "Ajouter" → file picker (accept: `application/pdf,image/jpeg,image/png,image/webp`, max 5 MB).
2. Validate → upload → show filename pill with type chip + `×` remove.
3. On step submit (or Settings save): Server Action PATCH with `kyc_docs` array.

### Sidebar Nav Disabled State

Disabled items (`cursor-default`, no `<Link>`) must still render their icon + label for layout stability. "Bientôt" badge is part of the nav item markup, not a tooltip. Future phases flip `disabled` to `false` — no structural change needed.

### `next=` Query Param Allowlist

The `/fr/login?next=` parameter is validated against an explicit allowlist before redirect. Allowlist for Phase 24:
```
['/coach/onboarding', '/coach/dashboard', '/coach/settings']
```
Any other value falls back to `/coach/dashboard`. This is a security contract — executor must not use open-redirect.

## Accessibility Contracts

- All form inputs have associated `<label>` elements (not placeholder-only).
- Wizard progress bar: `role="progressbar" aria-valuenow={step} aria-valuemin={1} aria-valuemax={3} aria-label="Étape {step} sur 3"`.
- Disabled sidebar nav items: `aria-disabled="true"` on the `<span>` wrapper.
- File upload trigger: `<label>` wrapping hidden `<input type="file">` (not a `<button>` triggering `click()` on a hidden input — avoids focus management issues).
- Status chips: include visually-hidden status label if color is the only differentiator.
- Error messages: `role="alert"` on the form-level error container; field-level errors use `aria-describedby`.
