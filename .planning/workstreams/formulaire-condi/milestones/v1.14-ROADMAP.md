## Key Technical Decisions

| Decision | Rationale |
|----------|-----------|
| SECURITY DEFINER function for trigger engine | Single Postgres function handles all 4 trigger types; avoids RLS bypass complexity per-route |
| Duplicate guard via unique constraint | `UNIQUE (form_id, athlete_id)` filtered on `status = 'pending'` — simpler than application-level checks |
| `yes_no` (underscore) as canonical type string | Matches mobile `FormQuestion` renderer switch-case; `yesno` was the pre-existing bug |
| `a.value` (not `a.answer_value`) for JSONB reads | `form_responses.answers` stores `[{question_id, value}]` — `answer_value` never existed |
| `n_sessions` (not `n`) in trigger config JSONB | `TriggerConfig.tsx` writes `n_sessions`; original SQL read `n` — JSONB key mismatch caused trigger to never fire |
| Overlay injected in `_layout.tsx` with AppState | Ensures blocking on launch AND on resume from background; no per-screen integration needed |
| Last 5 form responses in Claude system prompt | Bounded context injection (not unbounded); provides coaching relevance without exceeding token budget |
