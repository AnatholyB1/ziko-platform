<objective>
Fix BLOCKER-05: The SQL function create_form_instances_for_trigger (from migration 058) reads `trigger_config->>'n'` to match the configured session count. TriggerConfig.tsx writes `{ n_sessions: N }` to the DB — the key 'n' does not exist; `NULL::integer ≠ p_n_sessions` always; after_n_sessions trigger never creates form instances.

Fix: add a new migration that uses CREATE OR REPLACE FUNCTION to replace the function body, changing `trigger_config->>'n'` to `trigger_config->>'n_sessions'`. This is the safe approach: existing forms already have `n_sessions` stored, so the SQL-side fix works retroactively for all existing data without a data migration.

The existing migration 058 must NOT be edited (it is committed history). A new migration file is added.

Purpose: TRIGGER-02 and FORM-04 are fully blocked. No after_n_sessions form will ever trigger until this fix is applied.
