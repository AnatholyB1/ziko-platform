## Overview

A "Formulaires" tab added to the client detail sheet in the coach CRM. The tab lists every form instance assigned to that athlete — submitted forms show their date and are expandable to reveal the full Q&A transcript; pending forms show an "En attente" badge and are not expandable. The tab follows the exact same server-component + client-component split as all other client detail tabs (journal, sleep, cardio, etc.).

CLAUDE-01 and CLAUDE-02 are **backend-only requirements** — they inject the last 5 submitted form responses into the Claude system prompt context. No UI is needed for these two requirements. They are documented here for traceability only and must be implemented in the Hono AI context layer, not in any React component.

Design persona: Consistent with Phase 03 CRM aesthetic — Linear-precision data tool. The response viewer is a read-only data surface. Expand/collapse is the only interaction. No editing, no delete, no modals.

- Type indicator chip (right of question label): `bg-[#F0EFE9] text-[#6B6963] rounded px-1.5 py-0.5 text-xs float-right` — shows question type: "Texte libre" / "Échelle 1–10" / "Oui / Non" / "Choix unique"
- Divider between Q&A pairs: `border-b border-[#E2E0DA]` below each pair except last, with `pb-4` on the pair container

**Bottom of expanded panel:**
- `text-xs text-muted italic mt-2` — "Soumis le {DD MMM YYYY à HH:MM}"

## Interaction Contracts

### Expand / Collapse (RESPONSES-02)

- Only submitted form rows are expandable. Pending rows have no expand behavior.
- State: `expandedInstanceId: string | null` managed in `ClientFormsContent` via `useState`.
- Click on a collapsed submitted row → set `expandedInstanceId = row.instance_id` → Q&A panel appears below the row.
- Click on an already-expanded row → set `expandedInstanceId = null` → Q&A panel collapses.
- Only one row can be expanded at a time — clicking a second row auto-collapses the first (accordion behavior: `expandedInstanceId` is a single value, not an array).
- Pending rows: no click handler, `cursor-default`, no chevron icon.

### Expand panel reveal animation

- CSS transition only — no GSAP needed for this phase (table expand is simpler than form builder cards).
- Expanded panel: `transition-all duration-200 ease-out` on `max-height` + `opacity`.
- Collapsed state: `max-height: 0; opacity: 0; overflow: hidden`
- Expanded state: `max-height: 600px; opacity: 1` (600px is generous upper bound for any realistic Q&A list)
- Duration: 200ms — matches Phase 03 card expand timing.

### Sorting behavior

- Submitted rows appear first, sorted by `submitted_at DESC` (most recent at top).
- Pending rows appear below all submitted rows, regardless of creation date.
- Sorting is applied server-side when fetching — the API response should already be in this order. If not, `ClientFormsContent` must sort before rendering.

### Tab navigation

- `ClientTabStrip` is already a client component using `usePathname()`. Adding the "Formulaires" tab requires only one line added to the `TABS` array — no other changes to the tab strip.
- The active tab detection uses `pathname.endsWith('/forms')`.

## API Integration Reference

All API calls use the server-component pattern from existing tab pages: `createServerSupabase()` to get the coach JWT → fetch Hono API with `Authorization: Bearer {token}`.

### GET /coach/clients/:clientId/forms

```
URL: ${process.env.NEXT_PUBLIC_API_URL}/coach/clients/:clientId/forms
Method: GET
Auth: Bearer {coach_access_token}
Implemented by: Phase 01
```

**Response shape:**

```ts
interface FormInstancesResponse {
  forms: FormInstance[];
}

interface FormInstance {
  instance_id: string;            // UUID — used as key + expandedInstanceId
  form_id: string;                // UUID
  form_title: string;             // Display title in FORMULAIRE column
  status: 'pending' | 'submitted';
  submitted_at: string | null;    // ISO 8601 — null for pending
  question_count: number;         // For "N réponses" cell
  answers: FormAnswer[] | null;   // null for pending; populated for submitted
}

interface FormAnswer {
  question_id: string;
  question_label: string;         // The question text (displayed in Q&A transcript)
  question_type: 'text' | 'scale' | 'yes_no' | 'choice';
  answer_value: string | number;  // Raw value from form_responses table
}
```

**Sorting contract:** API should return submitted rows first (ordered by `submitted_at DESC`), then pending rows. If API does not sort, `ClientFormsContent` must apply this sort before rendering:

```ts
const sorted = [
  ...forms.filter(f => f.status === 'submitted').sort(
    (a, b) => new Date(b.submitted_at!).getTime() - new Date(a.submitted_at!).getTime()
  ),
  ...forms.filter(f => f.status === 'pending'),
];
```

**Answer display mapping:**

```ts
function formatAnswerValue(type: string, value: string | number): string {
  if (type === 'scale') return `${value} / 10`;
  if (type === 'yes_no') return value === 'yes' ? 'Oui' : 'Non';
  return String(value); // text and choice — display as-is
}
```
