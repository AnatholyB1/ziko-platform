# UI-SPEC: Phase 04 — Athlete Blocking Overlay (Mobile)

> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
> **This document is the written contract. Figma frames (once created by executor) are the visual source of truth.**

## Overview

A full-screen `Modal` (presentationStyle="fullScreen") rendered at root layout level in `_layout.tsx`. It intercepts the entire app when the athlete has ≥1 pending conditional form assigned by their coach. The athlete cannot dismiss or navigate past this overlay — it is the only interaction surface until all pending forms are submitted sequentially.

Design persona: Clean, focused, purposeful. No decorative elements — the overlay must feel efficient and respectful of the athlete's time. Every screen conveys "you're 1 step closer to training." Orange primary color is used sparingly and with intention: progress, selection, and the CTA. The athlete should feel guided, not trapped.

Structure mirrors `NotificationPermissionModal`: `Modal` + `Animated.View` for full-screen fade handling. No StyleSheet — inline style objects throughout. No NativeWind (root-level modal context). Uses `useThemeStore` tokens directly. `showAlert` from `@ziko/plugin-sdk` for error handling.

**Design decision (Claude's Discretion — D resolved here):**

| Token Name | Hex | Usage in overlay |
|-----------|-----|-----------------|
| `theme.background` | `#F7F6F3` | Full-screen modal background |
| `theme.surface` | `#FFFFFF` | Input area bg, unselected option card bg, unselected scale button bg |
| `theme.border` | `#E2E0DA` | Card strokes, input strokes, unselected scale button strokes, dividers |
| `theme.primary` | `#FF5C1A` | Accent strip, selected states, progress fill, CTA button, submit button |

**Color discipline:**
- `theme.primary` (#FF5C1A) is reserved for: accent strip, progress bar fill, selected states (scale button, option card border + tint), CTA button, counter advance pill
- Never use primary on body text — only on interactive selected states and action elements
- Skeleton / loading fills: `#E2E0DA` (border color) — never primary orange for loading states

### Color Distribution (60/30/10)

### Answer validation per question type (D-05)

| Type | Valid condition |
|------|----------------|
| `text` | `answer.trim().length > 0` |
| `scale` | `answer >= 1 && answer <= 10` (any selection) |
| `yes_no` | `answer === 'yes' \| answer === 'no'` |
| `choice` | `answer` is one of `question.choices[]` |

Submit CTA is disabled (`opacity: 0.4`, `pointerEvents: 'none'`) until ALL questions in the form have a valid answer.

### ScrollView vs pagination (Claude's Discretion — resolved here)

Using `ScrollView` for all question types. Rationale: most forms will have 3–8 questions. A single scrollable page avoids navigation state complexity, allows the athlete to review/edit previous answers before submitting, and aligns with the stated D-07 contract of an "instant replace" between forms (not individual question pages). `KeyboardAvoidingView` wraps the root to prevent keyboard overlap on TextInput questions.

## Motion Design

> Platform: React Native (Expo SDK 54)
> Engine: `react-native` Animated API
> Personality: Snappy + purposeful — 250ms maximum durations, `useNativeDriver: true` everywhere

### Motion contract per screen

| Screen / Element | Animation | Duration | Easing | React Native Pattern |
|----------------|-----------|----------|--------|---------------------|
| Overlay mount (S1) | Fade in from opacity 0 | 250ms | ease-out (spring) | `Animated.spring(fadeAnim, { toValue: 1, tension: 60, friction: 9, useNativeDriver: true })` |
| Overlay dismiss (S5) | Fade out to opacity 0 | 300ms | linear (D-08 exact) | `Animated.timing(fadeAnim, { toValue: 0, duration: 300, useNativeDriver: true }).start(() => unmount())` |
| Scale button selection | Scale pop feedback | 100ms | bounce | `Animated.spring(btnScale, { toValue: 1.08, tension: 200, friction: 7, useNativeDriver: true })` then back to 1.0 |
| Option card selection (Yes/No, Radio) | Scale dip + immediate rebound | 80ms | — | `Animated.sequence([Animated.timing(scale, { toValue: 0.97, duration: 80, useNativeDriver: true }), Animated.spring(scale, { toValue: 1, tension: 200, friction: 8, useNativeDriver: true })])` |
| CTA button press | Scale dip | 100ms | — | `Animated.sequence([Animated.timing(ctaScale, { toValue: 0.97, duration: 100, useNativeDriver: true }), Animated.spring(ctaScale, { toValue: 1, tension: 160, friction: 8, useNativeDriver: true })])` |
| Submit → next form (S4) | No animation — instant replace | — | — | `setCurrentIndex(i + 1)` — no Animated call (D-07) |
| Progress bar fill | Width tween on question advance | 300ms | ease-out | `Animated.timing(progressWidth, { toValue: (answered/total) * barWidth, duration: 300, useNativeDriver: false })` — note: `useNativeDriver: false` for width |
| Counter pill advance | Text replace — no animation | — | — | React state update only |
| Question fade-in (on ScrollView initial render) | Stagger opacity 0→1 | 200ms base + 40ms per item | ease-out | `Animated.stagger(40, questions.map((_, i) => Animated.timing(itemAnim[i], { toValue: 1, duration: 200, useNativeDriver: true })))` |
| TextInput focus | Border color swap | instant | — | State-driven style change, no Animated needed |
| Keyboard avoid | Handled by KeyboardAvoidingView | system | — | `behavior="padding"` on iOS, `behavior="height"` on Android |

### Animated.Value setup template

```tsx
// In PendingFormsOverlay component:
const fadeAnim = useRef(new Animated.Value(0)).current;          // starts invisible
const progressAnim = useRef(new Animated.Value(0)).current;      // progress bar width

// Mount: fade in
useEffect(() => {
  if (isVisible) {
    Animated.spring(fadeAnim, {
      toValue: 1,
      tension: 60,
      friction: 9,
      useNativeDriver: true,
    }).start();
  }
}, [isVisible]);

// Dismiss (last form done):
const dismissOverlay = () => {
  Animated.timing(fadeAnim, {
    toValue: 0,
    duration: 300,
    useNativeDriver: true,
  }).start(() => {
    setPendingForms([]);
  });
};
```

```tsx
// In QuestionScale component:
const scaleAnimValues = useRef(
  Array.from({ length: 10 }, () => new Animated.Value(1))
).current;

const handlePress = (value: number) => {
  const idx = value - 1;
  Animated.sequence([
    Animated.timing(scaleAnimValues[idx], {
      toValue: 1.08, duration: 80, useNativeDriver: true,
    }),
    Animated.spring(scaleAnimValues[idx], {
      toValue: 1, tension: 200, friction: 8, useNativeDriver: true,
    }),
  ]).start();
  onSelect(value);
};
```

```tsx
// In SubmitButton component:
const ctaScaleAnim = useRef(new Animated.Value(1)).current;

const handlePressIn = () => {
  Animated.timing(ctaScaleAnim, {
    toValue: 0.97, duration: 100, useNativeDriver: true,
  }).start();
};

const handlePressOut = () => {
  Animated.spring(ctaScaleAnim, {
    toValue: 1, tension: 160, friction: 8, useNativeDriver: true,
  }).start();
};
```

**Critical constraint:** `useNativeDriver: true` on all opacity/transform animations. Only `useNativeDriver: false` for layout properties (width, height, padding) — progress bar width tween is the only exception.

## API Integration Reference

Both endpoints are implemented in Phase 01. The mobile overlay consumes them directly.

### GET /athlete/forms/pending

```
URL: ${EXPO_PUBLIC_API_URL}/athlete/forms/pending
Method: GET
Auth: Bearer {session.access_token}
```

**Response shape:**
```ts
interface PendingFormsResponse {
  forms: PendingForm[];
}

interface PendingForm {
  instance_id: string;       // UUID — used for submit
  form_id: string;           // UUID
  form_title: string;        // Display title
  question_count: number;    // For badge
  questions: FormQuestion[];
}

interface FormQuestion {
  id: string;                // UUID — used as answer key
  type: 'text' | 'scale' | 'yes_no' | 'choice';
  label: string;             // Question text displayed to athlete
  choices?: string[];        // Only for type === 'choice'
}
```

**Query key:** `['pending-forms', userId]`
**Enabled condition:** `!!userId`
**staleTime:** 0 (always refetch — blocking overlay must show latest state)

### POST /athlete/forms/:instanceId/submit

```
URL: ${EXPO_PUBLIC_API_URL}/athlete/forms/{instance_id}/submit
Method: POST
Auth: Bearer {session.access_token}
Content-Type: application/json
```

**Request body:**
```ts
interface SubmitFormBody {
  answers: FormAnswer[];
}

interface FormAnswer {
  question_id: string;       // matches FormQuestion.id
  value: string | number;    // text → string, scale → number (1-10), yes_no → 'yes'|'no', choice → string
}
```

**Success response:** `{ success: true }` or `{ instance_id, status: 'submitted' }`
**Error handling:** `showAlert('Erreur', 'La soumission a échoué. Vérifie ta connexion.', [...])` — D-06 contract

### Answer value type mapping

| Question type | value type | example |
|---------------|-----------|---------|
| `text` | `string` | `"Je me sens bien cette semaine"` |
| `scale` | `number` | `7` |
| `yes_no` | `string` (`'yes'` or `'no'`) | `'yes'` |
| `choice` | `string` (one of choices[]) | `"Gagner en force"` |
