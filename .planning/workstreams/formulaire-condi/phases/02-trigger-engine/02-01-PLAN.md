<objective>
Create Postgres migration 058 that adds the SECURITY DEFINER function `create_form_instances_for_trigger`. This function is the shared engine for all 4 trigger types in Phase 02 — every trigger handler (TRIGGER-01 through TRIGGER-04) calls it via `supabase.rpc()` from Hono without needing a user JWT.

Purpose: The existing RLS policy `form_instances_insert` requires `auth.uid() = coach_id`, making server-side inserts from webhook and cron contexts impossible with the publishable key only. The SECURITY DEFINER function runs as the function owner (postgres role) and bypasses RLS for the targeted INSERT, while enforcing business rules (active form, matching trigger type, correct coach ownership) inside the function body.

Output: `supabase/migrations/058_form_trigger_engine.sql` — one SQL file with the function definition and REVOKE/GRANT statements.
</objective>

    `public.create_form_instances_for_trigger(p_trigger_type text, p_athlete_id uuid, p_coach_id uuid, p_n_sessions integer DEFAULT NULL, p_date text DEFAULT NULL) RETURNS integer`

    Function behavior:
    - LANGUAGE plpgsql, SECURITY DEFINER, SET search_path = public
    - Queries `coach_forms` WHERE `coach_id = p_coach_id` AND `status = 'active'` AND `trigger_config->>'type' = p_trigger_type`
    - For `after_n_sessions` type: additionally filter `(trigger_config->>'n')::integer = p_n_sessions`
    - For `fixed_date` type: additionally filter `trigger_config->>'date' <= p_date` (handles past-due dates too)
    - For `first_contact` and `manual` types: no extra filter beyond type match
    - For each matching form, INSERT INTO `form_instances(form_id, athlete_id, status)` VALUES (form.id, p_athlete_id, 'pending') ON CONFLICT ON CONSTRAINT form_instances_no_dup_pending DO NOTHING
    - Returns the count of rows actually inserted (use GET DIAGNOSTICS v_count = ROW_COUNT or accumulate per form)
    - Wrap in BEGIN/EXCEPTION block: re-raise unexpected exceptions, log via RAISE WARNING

    Security grants:
    - REVOKE ALL ON FUNCTION public.create_form_instances_for_trigger(...) FROM PUBLIC
    - GRANT EXECUTE ON FUNCTION public.create_form_instances_for_trigger(...) TO authenticated
    - GRANT EXECUTE ON FUNCTION public.create_form_instances_for_trigger(...) TO service_role

    Migration header must include: `SET LOCAL lock_timeout = '5s';` (per established migration pattern from 045).

    Do NOT add a TRIGGER-based auto-fire — this function is called explicitly from application code only.
    Do NOT use `is_coach_of()` inside the function — it is already filtering by `coach_id = p_coach_id` which is sufficient.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Elevation of Privilege | create_form_instances_for_trigger | mitigate | Function filters by coach_id = p_coach_id before inserting — a caller cannot create instances for another coach's forms |
| T-02-02 | Tampering | form_instances INSERT via RPC | mitigate | ON CONFLICT DO NOTHING prevents duplicate pending instances; UNIQUE index is the hard guard |
| T-02-03 | Spoofing | p_athlete_id parameter | mitigate | In TRIGGER-01 and TRIGGER-04 paths, p_athlete_id is sourced from auth.uid() or coach-verified client list — not from unvalidated client input |
