Wire two trigger types to the `create_form_instances_for_trigger` RPC defined in Plan 02-01:

1. **TRIGGER-01 — First-contact hook**: After `redeemInvitation` returns `ok: true` in `service.ts`, fire a non-blocking call to `create_form_instances_for_trigger('first_contact', athleteId, coachId)`. Purpose: These two trigger types share Wave 1 with Plan 02-01 because they can be coded as soon as the RPC exists in the DB — they do not depend on webhook or cron infrastructure.

Output: Modified `service.ts` (TRIGGER-01 hook) + modified `forms.ts` (new /send route).

    1. Extract `userId` from `c.get('auth')`
    2. Extract `id` from `c.req.param()`
    3. Parse body: `{ athlete_ids }` — expect `athlete_ids: string[]`; if missing or not array, return 400 `{ error: 'athlete_ids must be a non-empty array of UUIDs' }`

       - `skipped` = athlete_ids who already had a pending instance (silently skipped by ON CONFLICT DO NOTHING)

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-02-04 | Spoofing | /send athlete_ids array | mitigate | UUID regex validation on every entry before passing to RPC; coach ownership check prevents sending forms they don't own |
