    2. `SET LOCAL lock_timeout = '5s';` — matches migration 034/035 pattern.

    3. `CREATE TABLE IF NOT EXISTS public.coach_branding` with columns:
       - `coach_id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE`
       - `primary_color TEXT NOT NULL CHECK (primary_color ~ '^#[0-9A-Fa-f]{6}$')` — per D-04
       - `logo_url TEXT NULL` — stores Supabase bucket path, not full URL (per CONTEXT.md specifics)
       - `tone TEXT NULL CHECK (tone IN ('Motivant', 'Analytique', 'Bienveillant', 'Exigeant'))` — per D-05; TEXT CHECK not ENUM
       - `created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
       - `updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`

    4. updated_at trigger — reuse existing handle_updated_at() from migration 001, same pattern as migration 034:
       `CREATE TRIGGER trg_coach_branding_updated BEFORE UPDATE ON public.coach_branding FOR EACH ROW EXECUTE FUNCTION public.handle_updated_at();`

    5. `ALTER TABLE public.coach_branding ENABLE ROW LEVEL SECURITY;`

    6. Two RLS policies:
       - Coach owns their row (ALL operations):
         `CREATE POLICY "coach_branding_own" ON public.coach_branding FOR ALL USING (auth.uid() = coach_id) WITH CHECK (auth.uid() = coach_id);`
       - Linked athlete reads coach row (SELECT only) — per D-17, CONTEXT.md code_context flipped pattern:
         `CREATE POLICY "coach_branding_athlete_read" ON public.coach_branding FOR SELECT USING (public.is_coach_of(coach_id, auth.uid()));`
         Note: `is_coach_of(coach_id, auth.uid())` — coach_id FIRST, auth.uid() second. This is the correct signature matching migration 035 where the function is `is_coach_of(coach UUID, client UUID)`.

    7. Public storage bucket creation — use Supabase `INSERT INTO storage.buckets` syntax:
       `INSERT INTO storage.buckets (id, name, public) VALUES ('coach-logos', 'coach-logos', true) ON CONFLICT (id) DO NOTHING;`

    8. Storage RLS policy for the coach-logos bucket — coaches can insert/update their own logos (path prefix = coach_id):
       `CREATE POLICY "coach_logos_coach_write" ON storage.objects FOR ALL TO authenticated USING (bucket_id = 'coach-logos' AND (storage.foldername(name))[1] = auth.uid()::text) WITH CHECK (bucket_id = 'coach-logos' AND (storage.foldername(name))[1] = auth.uid()::text);`
       And public read (bucket is public, but explicit policy for clarity):
       `CREATE POLICY "coach_logos_public_read" ON storage.objects FOR SELECT USING (bucket_id = 'coach-logos');`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Supabase Auth → coach_branding table | All reads/writes are mediated by RLS with auth.uid() |
| coach_id path prefix → storage.objects | Coach can only write to bucket paths prefixed with their own UUID |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | coach_branding.primary_color | mitigate | `CHECK (primary_color ~ '^#[0-9A-Fa-f]{6}$')` enforced at DB level — rejects any non-hex value |
| T-01-02 | Tampering | coach_branding.tone | mitigate | `CHECK (tone IN ('Motivant','Analytique','Bienveillant','Exigeant'))` allows only the four valid values |
| T-01-03 | Elevation of Privilege | coach_branding RLS | mitigate | Coach-own policy uses `auth.uid() = coach_id`; athlete read uses `is_coach_of(coach_id, auth.uid())` SECURITY DEFINER — cannot be bypassed |
| T-01-04 | Tampering | storage.objects coach-logos | mitigate | Storage policy checks `(storage.foldername(name))[1] = auth.uid()::text` — coach can only write under their own UUID prefix |
| T-01-05 | Information Disclosure | coach-logos bucket public | accept | Public bucket is intentional (D-16) — logo images are non-sensitive public branding assets; no PII stored in this bucket |
</threat_model>
