# Phase 23 - CONTEXT (Atelier IA de creation de programme)

Branche `phase/23-atelier` (base `milestone/v1.20`). Exigences ATEL-01..06 et ATEL-10 (ATEL-07..09 = P24, hors scope, mais le brouillon est concu pour que P24 puisse relancer l'atelier). Maquette : `phases/04-maquettes-reference/lot-A/` (A10..A15) ; la maquette gagne sur le contrat. Decisions utilisateur deja prises (non rediscutees) : bouton plein = `getActionPrimary(theme)` (#CF4509) ; credits via `creditCheck`/`creditDeduct`, journal `ziko_ai_cost_log` ; appels automatiques absorbes avec plafond journalier.

## Decisions verrouillees (D-xx)
- D-01 Route dediee `POST /ai/workshop/stream` (SSE), distincte de `/ai/chat/stream` : outils propres a l'atelier (schemas imbriques, impossibles dans `AITool` du registre qui n'accepte que des scalaires), prompt propre, `stopWhen: stepCountIs(8)`. Le chat generique n'est pas modifie.
- D-02 Le brouillon vit en base dans une table dediee `ziko_workshop_drafts` (RLS own, `revision` entiere). Il n'est PAS une ligne de `ziko_ai_generated_programs` tant que l'utilisateur n'a pas enregistre : la liste P7 n'affiche donc jamais de brouillon et P7/P24 ne sont pas touches. "Enregistrer" = insert d'une ligne INACTIVE dans `ziko_ai_generated_programs` ; l'activation reste le chemin unique de P7 (`ziko_set_active_program`).
- D-03 Edition live (ATEL-05) : l'IA modifie le brouillon par outils (`workshop_set_draft`, `workshop_edit_exercise`...) ; l'utilisateur edite a la main par `PATCH /ai/workshop/drafts/:id` (operations typees, `expected_revision`, 409 si perime). Aucune edition manuelle ne consomme de credit (A-6). Chaque modification renvoie le programme complet + `revision` (evenement SSE `draft`).
- D-04 Forme du programme = celle que `workoutPlan.ts` (P6) sait demarrer : `weeks[].sessions[].exercises[]` avec `day_of_week` ISO distincts, champs `sets`, `reps`, `rest_seconds`, plus champs optionnels precis pour le powerlifter : `pct_1rm`, `rpe`, `tempo`, `note`. `weeks_count`, `generated:true`, `workshop:true` poses. Semaines multiples reelles (S1-S8 de A10) : une entree `weeks[]` par semaine.
- D-05 Recherche web (ATEL-02) : outil `workshop_web_search` = sous-appel Anthropic avec l'outil natif `webSearch_20250305` (meme cle `ANTHROPIC_API_KEY`, aucun nouveau secret). Absorbe : pas de credit supplementaire, journalise dans `ziko_ai_cost_log` avec `source='workshop_web_search'`, max 2 par message et plafond journalier par utilisateur (`WORKSHOP_WEB_SEARCH_DAILY_CAP = 20`, compte dans `ziko_ai_cost_log`). Plafond atteint : l'outil renvoie un message "limite atteinte", l'IA continue sans web.
- D-06 Skills (ATEL-03) : bibliotheque statique versionnee dans le code (`workshop/skills.ts`, 8 skills : powerlifting pic de force, powerlifting bloc de volume, hypertrophie PPL, force 5x5/5-3-1, debutant full body, retour de blessure/deload, hybride force+cardio, calisthenics). Outils `workshop_list_skills` (ids + resume) et `workshop_load_skill(id)` (corps). Pas de table : zero migration pour le contenu, evolutif par PR.
- D-07 Contexte complet (ATEL-04) : `workshop/context.ts` assemble profil, objectifs, 12 dernieres seances avec exercices et meilleures series, 1RM estimes (Epley) par exercice les plus frequents, programmes precedents (nom, objectif, dates, actif ?), mesures recentes. Injecte (borne ~3500 car.) dans le prompt systeme a chaque message + outil `workshop_get_context` pour le detail d'un exercice. L'ecran A11 affiche les comptes reels (seances, programmes, records) via `GET /ai/workshop/info`.
- D-08 Credits (ATEL-10) : l'atelier reutilise le `kind` existant `chat` (creditCheck('chat') + creditDeduct('chat')), aucun nouveau kind, aucune migration de credits. Le cout AFFICHE est lu dans `CREDIT_COSTS.chat` cote serveur (`/ai/workshop/info` renvoie `cost`, `free_quota_left`, `balance`) : jamais "1 credit par message" en dur (le contrat disait 1, le gate reel coute 4). Echec avant le premier octet utile : reponse 502, donc rien n'est debite (A14). Echec apres des chunks : l'IA a bien travaille, debit conserve (meme regle que `/chat/stream`).
- D-09 Hors-ligne / reseau coupe : message conserve cote client, bouton Reessayer ; solde non modifie (le serveur ne debite qu'apres un statut < 400).
- D-10 Point d'entree : la feuille Creer de `programs.tsx` et l'etat vide routent `workout/atelier` au lieu de `workout/ai-generate`. `ai-generate.tsx` reste (ancienne generation) et n'est pas retire.
- D-11 Etat A15 (credits epuises) : le serveur repond 402 `insufficient_credits` ; l'ecran desactive la saisie, garde l'edition manuelle, affiche "Obtenir des credits". Le solde dans la barre vient de `/credits/balance` + `/ai/workshop/info`.

## Gray areas (reco marquee)
- G-1 [A CONFIRMER] `kind` de credits : reutiliser `chat` (4 credits, 1 gratuit/jour partage avec le chat) vs nouveau `workshop`. Reco : `chat` (zero changement d'economie v1.4) ; un tour d'atelier avec web+skills coute plus cher en tokens qu'un chat : a mesurer sur le 1 appel reel de l'orchestrateur avant de reviser.
- G-2 [A CONFIRMER] Plafond web search 20/jour/utilisateur et 2/message : valeurs de depart, ajustables dans `workshop/limits.ts`.
- G-3 [A CONFIRMER] Un brouillon par conversation, 5 brouillons actifs max par utilisateur (les plus anciens sont archives a l'enregistrement) ; pas de purge automatique en P23 (a traiter par un cron de nettoyage si besoin).
- G-4 [A CONFIRMER] Historique : les messages de l'atelier sont stockes dans `ziko_ai_conversations` / `ziko_ai_messages` avec `plugin_context = {"source":"workshop","draft_id":...}` (colonne existante, pattern de l'onboarding), donc le chat generique ne les mele pas... a verifier : `getOrCreateConversation` ne filtre pas par tag ; on lit uniquement l'historique par id depuis l'atelier.
- G-5 Pas d'ajout a `registry.ts` (l'atelier a ses propres outils, D-01). Seule modification partagee : `lib/autonomousCost.ts` (+1 source) et `app.ts` (+1 route).
