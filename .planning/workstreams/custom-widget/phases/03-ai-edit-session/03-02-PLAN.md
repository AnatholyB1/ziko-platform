    1. Extract `clientId` from `c.req.param('clientId')`.
    2. Extract `coachId` and `jwt` from `c.get('auth')` and the Authorization header.
    3. Parse body as `{ messages: Message[], currentWidgets: Widget[], conversation_id?: string }`.
    4. Call `getOrCreateConversation(coachId, conversation_id, jwt)` from `context/conversation.ts` to load or create a conversation and get its history.
    5. Build `allMessages` by prepending convo.history to the incoming messages array.
    6. Call `streamText` with:
       - `model: AGENT_MODEL`
       - `system:` the scoped system prompt (string literal — see below)
       - `messages: allMessages`
       - `tools: buildDashboardSDKTools(currentWidgets)` — per D-07 each request gets its own tool factory with the current widget state
       - `stopWhen: stepCountIs(2)` — per L-07/PITFALLS #13; NOT 5
       - `onStepFinish`: async callback that inspects the step's toolResults; if toolResults exist, iterate each result, extract `result.widgets` (the updated Widget array), and write `data: ${JSON.stringify({type:'tool_result', widgets: result.widgets})}\n\n` to the stream. This is the atomic emission — never write partial tool output (PITFALLS #3).
    7. Set SSE headers BEFORE calling `stream()`: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`.
    8. Inside `stream(c, async (s) => { ... })`:
       a. Write `meta` event: `data: ${JSON.stringify({type:'meta', conversation_id: convo.conversationId})}\n\n`
       b. Iterate `result.fullStream` — on `text-delta` parts write `chunk` events; on `tool-error` log to console; skip other part types
       c. After the loop write `data: [DONE]\n\n`
       d. After the loop (outside try/catch or in finally), call `appendMessages` with `response.messages` from the streamText result — per PITFALLS #2 this MUST be called on every turn including tool-call turns. Use `await result.response` to get the `messages` array before calling appendMessages.
       e. On error: write `data: ${JSON.stringify({type:'error', error: msg})}\n\n` then `data: [DONE]\n\n`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Coach browser → /ai-edit | currentWidgets array arrives from client; must not be used as-is for DB writes in this handler |
| /ai-edit → Claude tools | Claude generates tool inputs; validated by buildDashboardSDKTools schema |
| /ai-edit → appendMessages | SSE stream may error mid-turn; appendMessages must still be attempted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering | currentWidgets from request body | mitigate | Tools validate each widget through WidgetSchema in applyAddWidget; update/remove/reorder operate on the incoming array without DB validation — acceptable since the PUT /save step will re-validate via WidgetSchema.parse |
| T-03-05 | Spoofing | JWT missing from ai-edit request | mitigate | authMiddleware applied to all dashboardsRouter routes via `dashboardsRouter.use('*', authMiddleware)` — rejects requests without valid JWT before hitting this handler |
| T-03-06 | DoS | Unbounded tool loops | mitigate | `stopWhen: stepCountIs(2)` limits to 1 tool call + 1 text step per turn; Claude cannot recurse more than 2 steps |
| T-03-07 | Information Disclosure | conversation_id guessing | accept | conversation rows have RLS policy (auth.uid() = user_id); another coach cannot read a different coach's conversation history |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No new package installs — all imports are existing packages (ai, hono, @supabase/supabase-js) |
</threat_model>
