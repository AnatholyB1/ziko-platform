## ⚠ Critical Gap: MEM-01 Apply Path (TemplatePicker never mounts)

### Root Cause

Two components make contradictory assumptions about "what a new dashboard looks like":

**Phase 01 — `db.ts:16`** (backend)
```ts
if (!data) return { schema_version: 1, widgets: DEFAULT_WIDGETS.widgets }
// returns 4 pre-built widgets for any new coach+athlete pair
```

**Phase 04-03 — `page.tsx:57`** (frontend)
```ts
if (isNewDashboard === null && config) {
  setIsNewDashboard(config.widgets.length === 0)
  // requires empty array — never true since backend always returns 4 widgets
}
```

**Result:** `isNewDashboard` is always `false`. `showTemplatePicker` is always `false`.
TemplatePicker never mounts. The template-apply flow is unreachable.

### Secondary Issue

Even if the trigger is fixed, `TemplatePicker` renders `null` when `templates.length === 0`
with no call to `onSkip()`. A first-time coach with no saved templates would be stuck.

### Affected Requirements

- **MEM-01** (partial — save path works, apply path broken)

### Fix Complexity: Small (1–2 hours)

**Option A (Recommended):** Change `getDashboardConfig` to return `{ schema_version: 1, widgets: [] }` for new pairs. Let frontend detect `config.widgets.length === 0` to show TemplatePicker. On skip or if templates empty, initialize from `DEFAULT_WIDGETS` on the frontend.

**Option B:** Add a `is_new: boolean` field to `getDashboardConfig` response (set to `true` when `maybeSingle` returns null). Frontend checks `is_new` instead of widget count — explicit signal, no ambiguity.

## Tech Debt

### Phase 01
- `DEFAULT_WIDGETS` widget IDs are generated once at module load via `randomUUID()`. All new-config responses share the same static IDs — potential key collision if the same coach views multiple clients simultaneously in separate tabs.
- `DELETE /coach/dashboards/:clientId` has no frontend caller (orphaned backend route).

### Phase 04
- `TemplateNamingModal` does not invalidate `['coach-memory']` query cache after successful PUT → templates saved in one session won't appear in TemplatePicker for up to 5 minutes without a page reload.
