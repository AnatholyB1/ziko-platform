<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → `apps/mobile/node_modules` | Third-party native code enters the build; a substituted or typosquatted package would ship signed into the app binary |
| `app.json` → EAS/CNG prebuild → signed iOS binary | Config declares a native capability (`com.apple.developer.applesignin`) that Apple's signing process trusts |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SC | Tampering | `npx expo install` of `@react-native-google-signin/google-signin` + `expo-apple-authentication` | mitigate | Both packages carry disposition `Approved` in RESEARCH.md's Package Legitimacy Audit (slopcheck `OK`, 855K/1.4M weekly downloads, 5.5/7 yr registry age, names confirmed verbatim in Supabase official docs) — no `[ASSUMED]`/`[SUS]` entries, so no blocking human checkpoint is required. Task 1 acceptance criteria assert the exact package keys landed in package.json, catching a near-miss/typosquat substitution. |
| T-01-01 | Elevation of Privilege | iOS entitlement declaration in `app.json` | mitigate | Single-source the `com.apple.developer.applesignin` key through the `expo-apple-authentication` config plugin (`usesAppleSignIn: true`) rather than a hand-written `ios.entitlements` entry, so the declared capability always matches what the plugin's own prebuild logic supports (RESEARCH Pitfall 5). Asserted negatively in Task 2's verify. |
| T-01-02 | Spoofing | Browser-redirect OAuth path (`expo-auth-session` / `signInWithOAuth`) | mitigate | Explicitly not installed. The redirect path returns tokens through a deep link the OS may hand to another app registered for the `ziko` scheme; the native-ID-token path (`signInWithIdToken`) never puts a credential on a URL. Asserted in Task 1's acceptance criteria as a negative dependency check. |
| T-01-03 | Information Disclosure | `apps/mobile/app.json` (committed) | accept | Nothing written by this plan is secret — `usesAppleSignIn` and the plugin name are public build metadata. The genuinely sensitive value in this phase (the Google Web client **Secret**) never enters this repo at all; it is typed directly into the Supabase dashboard in plan 01-03. |
</threat_model>
