## Overview

The v1.11 Notification System delivers end-to-end push and in-app notifications for the Ziko mobile app. Structured in 6 phases: infrastructure (tokens, schema, send service) → action-triggered push events → in-app inbox → scheduled cron reminders → user preferences → local device reminders and OTA update card.

---

## Key Accomplishments

1. **End-to-end push pipeline on real device** — EAS Dev Build, custom pre-permission modal, token UPSERT on startup, `addPushTokenListener` rotation, proven end-to-end with test push on physical device
2. **4 server-side push events live** — program assignment, invitation accepted (bidirectional), post-session summary (2-min delay via `waitUntil`), level-up (collapsed) via Supabase DB webhooks → Hono → Expo Push Service
3. **In-app notification center with live data** — `notificationStore` + TanStack Query, deep-link navigation, mark-read / mark-all-read, `setBadgeCountAsync` badge sync, Supabase Realtime subscription in `_layout.tsx`
4. **3 Vercel cron jobs** — streak-at-risk daily (21h UTC), receipt poll + dead-token cleanup (every 15min, CRON_SECRET auth), opt-in weekly digest (Sunday 9h UTC)
5. **Notification preferences with server enforcement** — master switch, 5 category toggles, quiet hours pickers; `notificationService.ts` checks all 3 gates before every send
6. **On-device local reminders** — per-habit daily `scheduleNotificationAsync` + workout-day WEEKLY triggers with cancel/reschedule on prefs change; OTA update card in notification center via `expo-updates`

---

## Architecture Decisions

| Decision | Rationale |
|----------|-----------|
| Expo Push Service (no Firebase Admin direct) | Simpler server-side — Expo handles APNs/FCM routing |
| `notificationService.ts` in Hono (not client-side) | Server controls prefs enforcement, idempotency, chunking |
| `notification_log` as unified inbox + audit log | Single source of truth for in-app center + receipt tracking |
| Supabase DB webhooks → Hono for PUSH-03/04 | Decoupled from mobile client; fires on DB state change |
| Vercel Cron for scheduled jobs (CRON_SECRET auth) | Zero extra infra; follows existing supplements.ts pattern |
| Local notifications for reminders (not server push) | Per-device scheduling; no server round-trip for personal reminders |
| `device_id` as stable MMKV/AsyncStorage UUID | Deterministic UPSERT on `(user_id, device_id)` |
