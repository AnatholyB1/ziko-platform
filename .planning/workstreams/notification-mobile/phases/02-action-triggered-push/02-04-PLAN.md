<task type="checkpoint:human-action" gate="blocking">
  <name>Task 1: Configure Supabase Database Webhooks for PUSH-03 and PUSH-04</name>
  <read_first>
    - backend/api/.env (or Vercel dashboard) — retrieve the value of WEBHOOK_SECRET that is configured in the production environment. You will need this exact value for the Supabase webhook headers.
  </read_first>
  <what-built>
    The Hono endpoint POST /push-events/supabase is deployed (by plan 02-03). It expects:
    - HTTP POST from Supabase
    - Header X-Webhook-Secret: {value of WEBHOOK_SECRET env var}
    - JSON body with fields: type, table, record, old_record
    Two webhooks need to be created in the Supabase Dashboard — one per event.
  </what-built>
  <how-to-verify>
    Go to Supabase Dashboard → Project → Database → Webhooks (sidebar).

    Create Webhook 1 — PUSH-03 (post-session summary):
    - Name: push_workout_session_end
    - Table: workout_sessions (schema: public)
    - Events: check UPDATE only (not INSERT, not DELETE)
    - HTTP Request:
      - Method: POST
      - URL: https://ziko-api-lilac.vercel.app/push-events/supabase
      - Headers: add one header:
        - Header name: X-Webhook-Secret
        - Header value: {your WEBHOOK_SECRET value from Vercel env}
    - HTTP Timeout: 5000ms (default is fine)
    - Click Save / Create webhook

    Create Webhook 2 — PUSH-04 (level-up):
    - Name: push_user_xp_level_up
    - Table: user_xp (schema: public)
    - Events: check UPDATE only
    - HTTP Request:
      - Method: POST
      - URL: https://ziko-api-lilac.vercel.app/push-events/supabase
      - Headers: add one header:
        - Header name: X-Webhook-Secret
        - Header value: {your WEBHOOK_SECRET value from Vercel env}
    - HTTP Timeout: 5000ms
    - Click Save / Create webhook

    Verify both webhooks appear in the list with status enabled.

    Smoke test PUSH-04 (fastest to test — no delay):
    1. In Supabase Table Editor, open the user_xp table.
    2. Find a row for your own user ID.
    3. Manually UPDATE the level column to a value higher than its current value (e.g. from 5 to 6).
    4. Within 30 seconds, check your device — you should receive a push: "Niveau supérieur ! 🏆" / "Tu viens de passer au niveau 6. Continue comme ça !"
    5. Also verify a row was written to notification_log with type='level_up' and status='sent'.

    Smoke test PUSH-03 (has 2-minute delay):
    1. In Supabase Table Editor, open the workout_sessions table.
    2. Find a session row where ended_at IS NULL (or INSERT a test row with ended_at = null).
    3. UPDATE that row's ended_at to NOW().
    4. Wait approximately 2 minutes and 30 seconds.
    5. Check your device — you should receive: "Séance terminée 🔥" / "Belle performance ! Regarde ton résumé."
    6. Verify notification_log row with type='post_session_summary' and status='sent'.

    If either push does not arrive:
    - Check Vercel function logs (Vercel Dashboard → Functions → push-events) for errors
    - Verify WEBHOOK_SECRET in Vercel env matches the header value in Supabase Dashboard
    - Check Supabase Dashboard → Webhooks → click the webhook → View logs to confirm it fired and got a 200
  </how-to-verify>
  <resume-signal>Type "webhooks configured" after both webhooks are active and at least one smoke test passes. Describe any issues if tests fail.</resume-signal>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04-01 | Spoofing | Supabase webhook configuration | mitigate | WEBHOOK_SECRET is set in Supabase as a custom header. Any external caller without the secret gets 401 from the Hono handler. Rotate WEBHOOK_SECRET if it is ever exposed — update both Vercel env and Supabase webhook header. |
| T-02-04-02 | Tampering | Webhook URL | accept | URL is the production Hono API (https://ziko-api-lilac.vercel.app/push-events/supabase). Any changes to the URL are only possible by someone with Supabase Dashboard access — same trust level as DB access. |
</threat_model>
