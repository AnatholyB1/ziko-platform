<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vercel Cron → Hono | Cron requests carry no JWT — auth is CRON_SECRET Bearer header |
| Hono → Supabase Admin | Admin client bypasses RLS; queries are scoped by explicit user_id conditions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | All three cron endpoints | mitigate | `verifyCronSecret()` — 401 if `Authorization` header != `Bearer ${CRON_SECRET}`; consistent with supplements.ts pattern (working cron in prod) |
| T-04-02 | Denial of Service | CRON-03 weekly digest | mitigate | idempotency_key UNIQUE in notification_log — duplicate fires are silently skipped at DB level; one digest per user per Sunday |
| T-04-03 | Information Disclosure | CRON-03 per-user queries | mitigate | Admin client queries always scoped with `.eq('user_id', userId)` equality filter; no cross-user data leakage |
| T-04-04 | Denial of Service | CRON-02 receipt poll unbounded growth | mitigate | `sent_at > NOW() - 24h` filter on notification_log query; receipts older than 24h are never queried |
| T-04-SC | Tampering | npm installs | accept | No new packages installed in this phase — zero supply-chain surface |
</threat_model>
