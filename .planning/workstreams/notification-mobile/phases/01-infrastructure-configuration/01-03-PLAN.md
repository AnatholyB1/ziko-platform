| Boundary | Description |
|----------|-------------|
| mobile → POST /notifications/token | User JWT in Authorization header; token string from OS is the payload |
| OS → expo-notifications | OS-provided push token is trusted; validated with isExpoPushToken() on the backend |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | useNotificationSetup token POST | mitigate | Request uses session.access_token (Supabase JWT); authMiddleware on backend validates it; token is registered only for the authenticated user |
| T-03-02 | Denial of Service | Android channel setup on every mount | accept | setNotificationChannelAsync is idempotent — calling with same channelId is a no-op; low risk |
| T-03-03 | Information Disclosure | MMKV notification_skip_count | accept | MMKV is device-local storage; no sensitive data; skip count is non-sensitive |
| T-03-04 | Tampering | notificationTask at module scope | accept | Task runs minimal code (no DB calls); iOS kills long background tasks; payload data is not written to DB in this task |
</threat_model>
