<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→Hono annotation write | Only coach may create/edit/delete annotations |
| client→Hono signed-url | Both coach and linked athlete may read; no other caller |
| Hono→Supabase Storage | Service key used; storage_path never exposed to clients |
| Hono→Expo Push API | One-time send per video; idempotencyKey prevents duplicate pushes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-01 | Elevation of Privilege | POST/PATCH/DELETE /annotations | mitigate | verify video.coach_id === auth.userId in every write handler before calling DB |
| T-46-02 | Elevation of Privilege | athlete POSTing annotations | mitigate | same coach_id check; athlete_id from JWT will not match coach_id |
| T-46-IDOR | Information Disclosure | GET /signed-url | mitigate | verify caller is coach_id OR athlete_id of that specific video before generating URL |
| T-46-03 | Spoofing | POST /send-feedback resend | mitigate | check video.status !== 'annotated' before updating; return 400 if already sent |
| T-46-04 | Tampering | annotation content | mitigate | content.length > 2000 → 400; timestamp_s >= 0 numeric check |
| T-46-SC | Tampering | npm installs | mitigate | no new packages in this plan — backend only extends existing code |
</threat_model>
