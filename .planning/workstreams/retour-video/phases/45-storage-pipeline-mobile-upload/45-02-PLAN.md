<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client→/upload-url | Authenticated athlete requests signed URL — coach link must be validated before issuing |
| /complete endpoint | Athlete declares upload complete — videoId from URL params is unverified client input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-04 | Spoofing | /upload-url path prefix | mitigate | path.startsWith(athleteId + '/') guard — athlete cannot generate URL for another user's path (Pitfall 4) |
| T-45-05 | Elevation of Privilege | /upload-url for unlinked athlete | mitigate | getActiveCoachForAthlete returns null for revoked/expired/missing links → 403 NOT_LINKED |
| T-45-06 | Denial of Service | /complete duplicate push notifications | mitigate | idempotencyKey: `video_uploaded_${videoId}` in notificationService.send() — notification_log UNIQUE constraint prevents duplicate delivery (Pitfall 5) |
| T-45-07 | Tampering | /complete videoId spoofing | mitigate | getActiveCoachForAthlete re-called in /complete — stale link rejected even if videoId is valid |
| T-45-08 | Information Disclosure | SUPABASE_SERVICE_KEY | mitigate | Key used only server-side in Hono; never returned to client; follows existing pattern from storage.ts and notifications.ts |
| T-45-SC | Tampering | npm/pip/cargo installs | accept | No new packages — all deps already in package.json |
</threat_model>
