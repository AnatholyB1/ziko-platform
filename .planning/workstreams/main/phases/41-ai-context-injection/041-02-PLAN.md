<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| frontend→/insights | chartData is coach-provided summary metrics injected into the AI prompt |
| frontend→/thresholds POST | operator and threshold_value fields from coach input; validated server-side |
| Supabase RLS | coach_metric_thresholds policy ensures cross-coach isolation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-41-04 | Elevation of Privilege | GET /:clientId/thresholds | mitigate | Explicit .eq('coach_id', coachId) + RLS policy — coach can only read own thresholds |
| T-41-05 | Tampering | POST /:clientId/thresholds operator field | mitigate | Server-side validation: operator must be '>' or '<'; DB CHECK constraint as additional layer |
| T-41-06 | Tampering | chartData in insights prompt | accept | chartData is coach-controlled compact metrics (numeric scalars only), not arbitrary client data; no PII injected into prompt |
| T-41-07 | Denial of Service | Auto-triggered insights on every sport/date change | mitigate | creditCheck('coach_chat') middleware gates the endpoint; exhausted credits return an error before Claude is called |
| T-41-08 | Elevation of Privilege | DELETE /:clientId/thresholds/:thresholdId | mitigate | .eq('coach_id', coachId).eq('client_id', clientId) explicit scoping on delete; RLS as additional layer |
  T-41-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan |
