# Plan 44-02: DB migration + media-url backend endpoint

## Objective

Two deliverables:
1. Supabase migration adding `coach_exercise_id` (nullable FK) to `program_exercises` and a storage policy letting athletes read coach-exercise files via the backend.
2. New `GET /coach/exercises/:id/media-url` endpoint — validates the athlete has a coach-athlete relationship with the exercise owner, then generates signed URLs for the exercise's video/photo using an admin Supabase client.

## must_haves

### truths
- Migration file `20260527_coach_exercise_id_program_exercises.sql` exists in `supabase/migrations/`
- `program_exercises.coach_exercise_id` is `uuid NULL REFERENCES coach_exercises(id) ON DELETE SET NULL`
- `GET /coach/exercises/:id/media-url` returns `{ video_url: string | null, photo_url: string | null }` in 200
- `GET /coach/exercises/:id/media-url` returns 404 when exercise not found; returns `{ video_url: null, photo_url: null }` when no valid coach-athlete relationship (graceful degradation per D-13)
- `coach_id` for the exercise is derived server-side (not supplied by client — IDOR prevention per D-14)
- Signed URLs have 1-hour expiry
- `SUPABASE_SERVICE_KEY` added to `backend/api/.env.example` (admin client for storage only)

### verification_commands
- Migration file exists: `ls supabase/migrations/20260527_coach_exercise_id_program_exercises.sql`
- `rtk tsc --noEmit` exits 0 in `backend/api/`
- `GET /coach/exercises/<valid-id>/media-url` with athlete JWT returns `{ video_url, photo_url }` (null if no media)

Note: The relationship table name — check `backend/api/src/coach/clients/` or coach invitations module for the table name used to track coach-athlete relationships. 1. Import `getMediaUrls` from `./db.js`.
2. Register route `GET /:id/media-url` BEFORE any `/:id` catch-all route (Hono static-before-param rule):
   ```
   exercisesRouter.get('/:id/media-url', async (c) => {
     const { userId: athleteUserId } = c.get('auth');
     const id = c.req.param('id');
     // UUID validation
     if (!/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i.test(id))
       return c.json({ error: 'Invalid exercise id' }, 400);
     try {
       const result = await getMediaUrls(id, athleteUserId);
       return c.json(result);
     } catch (err: any) {
       // never 500 — graceful degradation returns nulls
       return c.json({ video_url: null, photo_url: null });
     }
   });
   ```
3. This route authenticates via the existing `exercisesRouter.use('*', authMiddleware)` — no additional middleware needed.
</action>
