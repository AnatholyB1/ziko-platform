# Plan 44-01: Extend searchExercises to merge coach_custom exercises

## Objective

Extend `GET /coach/programs/exercises?q=` so the response merges global library exercises (from `exercises` table) with the authenticated coach's custom exercises (from `coach_exercises` table). Each item carries a `source: "global" | "coach_custom"` field. Custom exercises float first in the result list; globals follow alphabetically.

## must_haves

### truths
- `searchExercises()` in `backend/api/src/coach/programs/db.ts` accepts `coachId` as second parameter
- Response item shape: `{ id, name, category, source: "global" | "coach_custom", coach_exercise_id?: string }`
- Custom exercises (source `coach_custom`) appear first in the merged array, sorted by name, then global results sorted by name
- `GET /programs/exercises` route passes `coachId` extracted from `c.get('auth').userId`
- `q` shorter than 1 char still returns 400 (existing validation preserved)
- Global exercises NOT modified — `exercise_id` semantics unchanged

### verification_commands
- `rtk tsc --noEmit` exits 0 in `backend/api/`
- `GET /coach/programs/exercises?q=squat` with coach JWT returns `{ exercises: [...] }` where custom exercise items have `source: "coach_custom"` and `coach_exercise_id` set

## Tasks

### Task 1 — Update `searchExercises()` signature and implementation

<read_first>
- `backend/api/src/coach/programs/db.ts` lines 235–260 — existing `searchExercises()` implementation and sort logic
- `backend/api/src/coach/exercises/types.ts` — `CoachExercise` interface (fields: `id`, `name`, `category`, `video_path`, `photo_path`)
</read_first>

<action>
In `backend/api/src/coach/programs/db.ts`:

1. Change `searchExercises(jwt, query)` signature to `searchExercises(jwt, coachId: string, query: string)`.

2. After fetching global `exercises` rows (existing query, unchanged), add a second query for coach custom exercises:
   ```
   db.from('coach_exercises')
     .select('id, name, category')
     .eq('coach_id', coachId)
     .ilike('name', `%${query}%`)
     .limit(10)
   ```

3. Map global results to shape: `{ id, name, category, source: "global", coach_exercise_id: null }`.

4. Map custom results to shape: `{ id: ce.id, name: ce.name, category: ce.category, source: "coach_custom", coach_exercise_id: ce.id }`.
   Note: for custom exercises, `id` (used as the exercise identifier) equals `coach_exercise_id`.

5. Sort: custom results alphabetically by name first, then global results with the existing prefix-first sort logic.

6. Return `{ exercises: [...customSorted, ...globalSorted] }` (up to 20 total — 10 custom + 10 global, not merged limit).
</action>

<acceptance_criteria>
- `searchExercises` function signature in `db.ts` is `(jwt: string, coachId: string, query: string)`
- Function performs two Supabase queries: one on `exercises`, one on `coach_exercises` with `.eq('coach_id', coachId)`
- Both queries use `.ilike('name', \`%${query}%\`)` and `.limit(10)`
- Global items have `source: "global"` and `coach_exercise_id: null`
- Custom items have `source: "coach_custom"` and `coach_exercise_id` set to the item's `id`
- Custom items come before global items in the returned array
- TypeScript compiles with `rtk tsc --noEmit` in `backend/api/`
</acceptance_criteria>
