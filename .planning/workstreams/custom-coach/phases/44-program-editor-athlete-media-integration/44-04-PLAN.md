# Plan 44-04: Athlete media bottom sheet in workout/[id].tsx

## Objective

Add a read-only media bottom sheet modal to the exercise rows in `workout/[id].tsx`. When an athlete taps an exercise row that has a `coach_exercise_id`, the app fetches signed media URLs from the backend and displays a `Modal` (pageSheet) with the exercise name, description (if any), and video player or photo (video takes priority per D-10). Exercises without `coach_exercise_id` remain tap-inert (no modal per D-11).

## must_haves

### truths
- Exercise rows that have `coach_exercise_id !== null` respond to `onPress` (opens modal)
- Exercise rows with `coach_exercise_id` null/undefined have no `onPress` handler — tap is a no-op
- `Modal` uses `presentationStyle="pageSheet"` with `animationType="slide"`
- Video playback uses `expo-av` `Video` component (already installed `~16.0.8`); shown when `video_url` is non-null
- Photo display uses `Image` from react-native; shown only when `photo_url` non-null and `video_url` null (D-10)
- When both `video_url` and `photo_url` are null (no media), modal still opens and shows exercise name + description only (graceful per D-11)
- Fetch uses `EXPO_PUBLIC_API_URL + /coach/exercises/:id/media-url` with `supabase.auth.getSession()` token
- Loading state shown while fetching (spinner or skeleton)
- Close button (top-right `×`) dismisses modal; `onRequestClose` also dismisses
- `SafeAreaView + ScrollView` pattern inside modal (consistent with existing modals in the file)
- `showAlert` from `@ziko/plugin-sdk` used for errors (consistent with project rule)

### verification_commands
- `rtk tsc --noEmit` exits 0 in `apps/mobile/`
- Tapping an exercise row with `coach_exercise_id` set opens the pageSheet modal
- Tapping an exercise row WITHOUT `coach_exercise_id` does nothing

3. Add `fetchAndOpenMedia(coachExerciseId: string, exerciseName: string)` async function (inside the component, before the return):
   ```ts
   const fetchAndOpenMedia = async (coachExerciseId: string, exerciseName: string) => {
     setMediaExerciseName(exerciseName);
     setMediaVideoUrl(null);
     setMediaPhotoUrl(null);
     setMediaLoading(true);
     setShowMediaModal(true);
     try {
       const { data: { session } } = await supabase.auth.getSession();
       const apiUrl = process.env.EXPO_PUBLIC_API_URL ?? '';
       const res = await fetch(`${apiUrl}/coach/exercises/${coachExerciseId}/media-url`, {
         headers: { Authorization: `Bearer ${session?.access_token ?? ''}` },
       });
       if (res.ok) {
         const json = await res.json();
         setMediaVideoUrl(json.video_url ?? null);
         setMediaPhotoUrl(json.photo_url ?? null);
       }
     } catch {
       // graceful degradation — modal shows name only
     } finally {
       setMediaLoading(false);
     }
   };
   ```

## Threat Model

| Threat | Mitigation |
|--------|------------|
| T-44-04-01: Athlete supplies arbitrary coach_exercise_id in fetch | `coach_exercise_id` comes from DB row (`pe.coach_exercise_id`) — not user-entered; backend validates relationship |
| T-44-04-02: Signed URL leakage | Signed URLs are ephemeral (1h expiry, backend-generated); never stored on device |
| T-44-04-03: Missing session token | `session?.access_token ?? ''` → backend returns 401 → graceful degradation (nulls), no crash |
