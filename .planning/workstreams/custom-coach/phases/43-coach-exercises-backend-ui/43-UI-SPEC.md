> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
> **This document is the written contract. Figma frames are the visual source of truth.**

---

## Overview

A new "Exercices" section in the coach CRM web app where coaches can build and manage a personal library of custom exercises. Each exercise supports a name, description, targeted muscle groups, category, and optional video/photo demo attachments stored in Supabase Storage (`coach-exercises` bucket). The UI mirrors existing CRM patterns (Programs page layout, SessionSlideOver drawer, FileUploadRow pattern).

- Select border: `border-danger`

#### 3E. Hover state — Actions revealed

On `group-hover`:
- Edit button: `p-2 rounded-lg text-muted hover:text-text hover:bg-background transition-colors` with `IoPencilOutline text-base`
  - aria-label: "Modifier {name}"
  - action: opens ExerciseSlideOver in edit mode
- Delete button: `p-2 rounded-lg text-muted hover:text-danger hover:bg-red-50 transition-colors` with `IoTrashOutline text-base`
  - aria-label: "Supprimer {name}"

#### 3F. Delete confirm inline

When trash icon is clicked, the row expands below to show:

```
┌──────────────────────────────────────────────────────────────┐
```

- Expanded section: `border-t border-red-100 pt-3 pb-3 px-5 bg-red-50/50 rounded-b-2xl`
- Message: `text-sm text-text` — "Supprimer « {name} » ?"
- Sub-message: `text-xs text-muted mt-0.5` — "Cette action est irréversible. Les fichiers associés seront supprimés du stockage."
- Confirm button: `bg-danger text-white rounded-lg px-4 py-1.5 text-sm font-bold hover:bg-red-600 transition-colors`
- Cancel link: `text-sm text-muted hover:text-text mr-3`
- Note: This replaces `window.confirm()` — no browser dialog, consistent with coach CRM UX

> Personality: **Snappy + Fluid** — from MOODBOARD.md. Entrances 200ms `power2.out`, exits 150ms `power2.in`, feedback 100ms `power3.out`.

> Note: This is a Next.js web app. GSAP is the motion library. Framer Motion is NOT in the stack.

| Screen | Animation | Duration | Easing | GSAP Pattern |
|--------|-----------|----------|--------|--------------|
| Exercise Library | Page entrance | 200ms | power2.out | `gsap.from(".exercise-library", { y: 16, opacity: 0, duration: 0.2, ease: "power2.out" })` |
| Exercise Library | List stagger (populated) | 200ms + 40ms/item | power2.out | `gsap.from(".exercise-row", { y: 8, opacity: 0, duration: 0.2, stagger: 0.04, ease: "power2.out" })` |
| Exercise Library | Skeleton → content | 200ms | power2.out | `gsap.from(".exercise-row", { opacity: 0, scale: 0.99, duration: 0.2, ease: "power2.out" })` |
| Exercise Library | Filter pill switch | 100ms | power2.out | `gsap.to(activePill, { scale: 0.97, duration: 0.05, yoyo: true, repeat: 1 })` |
| SlideOver | Open (slide in) | 200ms | CSS `ease-out` | `transition-transform duration-200 ease-out translate-x-0` (Tailwind, no GSAP needed) |
| SlideOver | Close (slide out) | 150ms | CSS `ease-in` | `transition-transform duration-150 ease-in translate-x-full` |
| SlideOver | Form validation error | 300ms | none | `gsap.to(invalidField, { x: [-6, 6, -4, 4, 0], duration: 0.3, ease: "none" })` |
| SlideOver | Upload progress bar fill | continuous | power1.out | `gsap.to(progressFill, { width: pct + "%", duration: 0.3, ease: "power1.out" })` |
| SlideOver | Upload success appear | 200ms | back.out(1.4) | `gsap.from(checkmark, { scale: 0, duration: 0.2, ease: "back.out(1.4)" })` |
| SlideOver | Save button → saved | 150ms | power2.inOut | opacity + text swap |
| Exercise Row | Hover actions reveal | 150ms | CSS `ease-out` | `transition-opacity duration-150` (Tailwind) |
| Exercise Row | Delete confirm expand | 200ms | power2.out | `gsap.from(".delete-confirm", { height: 0, opacity: 0, duration: 0.2, ease: "power2.out" })` |
| Exercise Row | Row add (after create) | 200ms | power2.out | `gsap.from(".exercise-row:first-child", { y: -12, opacity: 0, duration: 0.2, ease: "power2.out" })` |
| Exercise Row | Row remove (after delete) | 150ms | power2.in | `gsap.to(deletedRow, { height: 0, opacity: 0, duration: 0.15, ease: "power2.in" })` |
| Exercise Row | Edit/delete button press | 100ms | power3.out | `gsap.to(btn, { scale: 0.94, duration: 0.1, yoyo: true, repeat: 1 })` |

## Accessibility

| Concern | Implementation |
|---------|---------------|
| SlideOver ARIA | `role="dialog"` + `aria-modal="true"` + `aria-labelledby` pointing to title |
| Backdrop | `aria-hidden="true"` on backdrop div |
| Escape key | `keydown` listener on window → calls `onClose()` |
| Focus trap | Focus moves to SlideOver first focusable element on open (exercise name input) |
| Focus restore | On SlideOver close, focus returns to the trigger button (edit/create CTA) |
| Muscle chips | Each chip is a `<button type="button">` with `aria-pressed` state |
| Delete confirm | Announced via `role="alert"` on the confirmation zone |
| File inputs | Label wraps hidden `<input type="file">` (consistent with FileUploadRow pattern) |
| Row actions | Edit/delete buttons have explicit `aria-label="Modifier {name}"` / `aria-label="Supprimer {name}"` |
| Filter pills | Filter bar is `role="group"` with `aria-label="Filtrer par catégorie"` |
| Loading | Skeleton rows have `aria-hidden="true"`, page announces `aria-busy="true"` while loading |
| Keyboard nav | Tab order: filter bar → exercise rows → create CTA. Within rows: name text → edit button → delete button |
| Color contrast | All text passes WCAG AA: `#1C1A17` on `#FFFFFF` = 17.5:1, `#6B6963` on `#FFFFFF` = 5.4:1, `#FFFFFF` on `#FF5C1A` = 3.1:1 (large text passes AA) |

## Design Decisions & Rationale

| Decision | Rationale |
|----------|-----------|
| SlideOver (not full page) | Consistent with SessionSlideOver UX; allows coach to see exercise list while editing |
| Inline delete confirm (not `window.confirm`) | Consistent with CRM quality bar; browser dialogs break the design system |
| Muscle chips (not a select) | Multi-select is visually clearer and faster for coaches; typically 2-4 muscles selected |
| Category = required, muscles = optional | Category drives filtering (UI-critical); muscles are metadata for Phase 44 (athlete view) |
| No folder/group rail | Too few exercises in Phase 43 to warrant folders (Phase 44+ can add if needed) |
| List layout (not grid) | Exercises are data rows, not media cards; list enables denser browsing + easier media badge scanning |
| Filter bar (not search-first) | Most coaches will browse by category (Force/Cardio/etc.) before searching by name |
| Signed URL stored as path, not URL | Per FileUploadRow pitfall comment: signed URLs expire; store storage path, generate signed URL on demand |
