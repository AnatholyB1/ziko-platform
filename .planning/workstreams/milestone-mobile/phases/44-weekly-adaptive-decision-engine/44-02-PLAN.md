<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Postgres rows → decision evidence | Everything this module returns becomes the `evidence` payload of an immutable decision; a fabricated or defaulted value here is unfalsifiable downstream |
| `current_focus_detail` JSONB → query routing | The focus type that selects which tables get read comes from a JSONB blob previously written by an AI tool |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-06 | Tampering | `fetchFocusScopedActivity` table routing | mitigate | `focus_type` is validated against the closed `FOCUS_SOURCE_MAP` key set and falls back to `'unassigned'` when unrecognised; table names are never interpolated from the JSONB value, so a poisoned `current_focus_detail` cannot steer a query at a table outside the map |
| T-44-07 | Repudiation | Empty/sparse activity results | mitigate | Zero rows are reported as real zeros with `tables_read` recording what was actually queried; the module never substitutes a generic or defaulted metric object, matching `onboarding-retroactive.ts`'s "never paper over empty aggregates" discipline |
| T-44-08 | Tampering | `met` verdict | mitigate | Computed in backend arithmetic from queried counts (`actual_value >= target_value`), never accepted from or influenced by model output — plan 44-03's decision call receives this verdict as input, it does not produce it |
| T-44-09 | Information Disclosure | Cross-athlete data in the review context | mitigate | Every query in this module filters `.eq('user_id', userId)` with the caller-supplied id; `session_sets` (which has no `user_id`) is reached only via session ids already scoped to that user |
</threat_model>
