# Phase 44 — UI Design Contract

> Visual and interaction contract for Phase 44's single athlete-facing UI element: the brief
> in-app "Ziko reviewed your week" reveal moment (CONTEXT.md D-03). Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** Phase 44 is overwhelmingly a backend phase (`coaching-engine/` module, cron,
> AI decision logic, `athlete_goals` table). The weekly review computation itself is invisible
> background work (D-01) — there is no new screen, no new nav entry, no visible UI for the
> engine's decision-making. This contract governs **only** the reveal overlay that surfaces
> after a review completes, and it is a **reuse-first** contract: D-03 explicitly locks reuse of
> the `FadeInUp`/celebration pattern already shipped in Phase 43's onboarding celebration
> (`apps/mobile/app/(auth)/onboarding/ziko-chat.tsx`'s `CelebrationOverlay`, itself derived from
> `apps/mobile/app/(auth)/onboarding/step-7.tsx`'s `OBReady`). Every token below is inherited
> from `43-UI-SPEC.md` unless explicitly called out as a delta for this phase.

## Spacing Scale

Declared values (must be multiples of 4). Identical token set to `43-UI-SPEC.md` — reused, not
redefined:

| Token | Value | Usage this phase |
|-------|-------|-------|
| xs | 4px | not used |
| sm | 8px | not used |
| md | 16px | CTA button `paddingVertical` |
| lg | 24px | Overlay content container `paddingHorizontal` |
| xl | 32px | Vertical gap between badge / headline / subcopy / CTA |
| 2xl | 48px | not used |
| 3xl | 64px | not used |

**Exceptions:** none — every spacing value in this phase's one UI element is one of the tokens
above, reused verbatim from Phase 43's `CelebrationOverlay` layout (`gap: 32`, `paddingHorizontal: 24`,
CTA `paddingVertical: 16`).

**Tab-bar clearance — explicit delta from Phase 43:** Phase 43's celebration lived inside the
`(auth)/onboarding/` stack, which has no tab bar, so the global `paddingBottom: 100` convention
did not apply there. Phase 44's reveal fires while the athlete is already inside `/(app)`, which
**does** have a tab bar. **Resolution: render this overlay as a native `<Modal presentationStyle="fullScreen">`** (see Screen & Interaction Contract below), the same technique the codebase
already uses for `PendingFormsOverlay` (`apps/mobile/src/components/PendingFormsOverlay.tsx`,
mounted in `apps/mobile/app/(app)/_layout.tsx`). A `Modal` presents above the tab bar entirely, so
**`paddingBottom: 100` does NOT apply here either** — do not add it, and do not embed this
overlay as in-place screen content inside a tab (which would require it).

## Screen & Interaction Contract

**Primary focal point:** the badge icon-circle (76×76, `sparkles` glyph, radial glow, largest shadow in the composition) is the visual anchor the athlete's eye lands on first — headline and subcopy read as supporting text beneath it, and the CTA is the sole secondary anchor. This ordering (badge → headline → subcopy → CTA) drives the `xl`-then-`md`-then-`lg` spacing rhythm below; do not give headline/subcopy typographic weight or color treatment that competes with the badge.

### Component reuse directive

Phase 43's `CelebrationOverlay` is currently a private, inline component inside
`ziko-chat.tsx` — not exported or shared. Recommendation for the planner: extract a shared
presentational component (e.g. `apps/mobile/src/components/ZikoRevealOverlay.tsx`) that both
Phase 43's onboarding celebration and this phase's weekly-review reveal can render with different
props (icon, headline key, body key, CTA key, dismiss behavior) — avoiding a second hand-copied
implementation of the same visual treatment. If extraction is out of scope for planning, duplicate
the exact token values documented above instead; the rendered result must be visually
indistinguishable from Phase 43's, aside from the deltas explicitly called out in this document
(icon, dismissibility, mount mechanism).

### Mount mechanism — delta from Phase 43

Phase 43's overlay is a full-screen early-return **inside** a screen component in a stack with no
tab bar (`(auth)/onboarding/`). Phase 44's reveal must work from *any* tab, at any point during a
normal app session, without requiring the athlete to be on a specific screen. **Follow the
existing `PendingFormsOverlay` precedent** (`apps/mobile/src/components/PendingFormsOverlay.tsx`,
mounted as a sibling to `<Tabs>` in `apps/mobile/app/(app)/_layout.tsx`):

```tsx
<Modal
  visible={isVisible}
  animationType="none"
  presentationStyle="fullScreen"
  statusBarTranslucent
>
  {/* content below, entrance handled by Animated.View / Reanimated FadeInUp, not the Modal's own animationType */}
</Modal>
```

- New sibling component (e.g. `WeeklyReviewRevealOverlay`), mounted in `apps/mobile/app/(app)/_layout.tsx` alongside the existing `PendingFormsOverlay`.
- Data source: a `useQuery` reading the athlete's most recent completed `weekly_focus` review state (exact field — `athlete_state.last_review_at` / `current_focus_summary`, per `44-RESEARCH.md`'s Recommended Project Structure — is backend's shape to finalize; this contract only requires that the overlay never renders until that data is confirmed present, see Grounding below).
- Fires **once per completed review**: compare the review's timestamp/id against a locally-persisted "last seen" marker (MMKV, mirroring the existing per-day cache-key pattern already used by `useAIDailyTip`). Never re-shows for a review the athlete has already seen.

### Badge icon — delta from Phase 43

Phase 43's badge used Ionicons `checkmark` (38px, white) to mean "you completed a task." This
phase's reveal is Ziko's own analysis, not an athlete-completed action — reusing `checkmark` would
misrepresent what happened. **Use Ionicons `sparkles`** (same 38px, white, same container/shadow
treatment) to represent "Ziko's insight," distinct from the onboarding mission's completion glyph.
Container size (76×76), radius (22), background (`#FF5C1A`), shadow, and `FadeInUp.springify().damping(12)` entrance are reused **verbatim** — only the glyph name changes.

### Dismiss behavior — delta from Phase 43

Phase 43's celebration is the terminal step of a **mandatory** flow (D-02: no skip anywhere).
Phase 44's reveal is a **retention beat during ordinary app use**, not a required step — the
athlete must always be able to get back to whatever they were doing:

- Single CTA button dismisses the overlay (closes the `Modal`, sets the "seen" marker). No
  forced navigation — dismissing returns the athlete to exactly the tab/screen they were on.
- Unlike Phase 43, **Android hardware back / swipe gestures should also dismiss** the overlay
  (set `onRequestClose` on the `Modal` to the same dismiss handler as the CTA) — this is not a
  gated flow, so there is no reason to trap the athlete.
- No separate "X" close icon needed — the CTA plus back/gesture dismissal is sufficient, keeping
  the visual identical to Phase 43's single-CTA layout.

### Grounding (no broken/empty reveal)

Mirrors Phase 43's D-14 grounding discipline: **this overlay must never render from incomplete or
failed review data.** If the query backing it doesn't return a real, confirmed-complete review
(e.g. the background `waitUntil()` computation is still running, or failed), the overlay simply
does not fire — no placeholder, no spinner, no error state shown to the athlete for a background
job they never explicitly requested. The review will be reflected in the app's normal state
(current focus display elsewhere) whenever it does complete; this reveal is a bonus retention
moment on top of that, never a blocking indicator of pending work.

### Copy applies regardless of trajectory

The AI's weekly decision can escalate, hold, or de-escalate the athlete's focus (D-04–D-06), and
per D-05/REWARD-01's non-punitive framing, **no outcome may read as a penalty.** This overlay uses
a **single** headline/subcopy template for all three trajectories — never a distinct "bad week"
variant — with the dynamic portion limited to the new focus text itself (which the AI already
generates non-punitively). Do not introduce trajectory-conditional copy branches.
