The alternative considered and rejected was a second small `generateObject` call to summarise the journal in prose. Export `composeRollingSummary(previous: string | null, context: WeeklyReviewContext, decision: WeeklyDecisionResult): string`. It:
  1. Builds one entry line, pipe-delimited and locale-neutral because this string is model-facing prompt input, never athlete-facing UI: the `weekOf` date, the `trajectory`, then the comparison rendered as `<target_metric> <actual_value>/<target_value> <verdict>` where verdict is `met`, `missed`, or `no_target` when `comparison.met` is null, then the rationale.

Sanitises the rationale before embedding it: collapse all newline and carriage-return characters to single spaces, collapse runs of whitespace, then hard-slice to `ROLLING_SUMMARY_RATIONALE_CHARS`. If a single entry alone still exceeds the char cap, hard-slice the final joined string to `ROLLING_SUMMARY_MAX_CHARS`. The function must return a string satisfying both caps for every possible input, including a pathological 10 KB `previous`.
  5. Is pure — no I/O, no clock read, no model call — so the cap is testable in isolation and cannot be violated by a network failure mid-review.
