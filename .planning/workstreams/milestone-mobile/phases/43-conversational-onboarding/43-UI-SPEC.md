# Phase 43 — UI Design Contract

> Visual and interaction contract for the Ziko conversational onboarding chat, its end-of-chat mission card, and the full-screen celebration overlay. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Revision note (2026-09-01):** fixed two checker BLOCK findings — typography scale consolidated to the declared 4 sizes / 2 weights with no carve-outs, and all spacing values now conform to the 4px grid with no non-multiple-of-4 exceptions. **Second revision pass (2026-09-01):** fixed the remaining Dimension 5 BLOCK — the Header's `paddingHorizontal` was `20`, a multiple of 4 but not a member of the declared spacing token set; changed to `16` (the `md` token), matching the input row's already-declared 16px padding. Also lightly clarified two single-word CTA labels (retry / force-finish) for readability. No product decisions changed; both passes are scale-conformance-only.

## Spacing Scale

Declared values (must be multiples of 4). No exceptions to this grid exist anywhere in this phase's screens:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, bubble corner-radius asymmetry |
| sm | 8px | Compact element spacing (input↔send-button gap, mission card internal gaps, chat-bubble vertical padding, `TextInput` vertical padding) |
| md | 16px | Default element spacing (bubble horizontal padding, card padding, input row padding, header horizontal padding) |
| lg | 24px | Section padding (chat screen outer container horizontal padding, celebration overlay content padding) |
| xl | 32px | Layout gaps (celebration overlay vertical rhythm) |
| 2xl | 48px | Major section breaks (not used this phase — single-screen flows only) |
| 3xl | 64px | Page-level spacing (not used this phase) |

**Notes:**
- The Ziko chat screen's outer container uses `paddingHorizontal: 24` (the `lg` token) — a 2px deviation from `step-7.tsx`'s legacy `22px` value, resolved in favor of strict grid conformance rather than a preserved exception. Visual difference from the adjacent step-7 screens is negligible at 2px and does not read as a discontinuity.
- The header uses `paddingHorizontal: 16` (the `md` token) — a 4px deviation from `ai/index.tsx`'s legacy `20px` value, resolved the same way for the same reason: strict grid conformance, no carved-out exception. The header's `paddingVertical: 16` was already grid-conformant and is unchanged.
- **`paddingBottom: 100` (global tab-bar-clearance rule) does NOT apply to this phase's two new screens.** Both the Ziko chat screen and the celebration overlay live inside `(auth)/onboarding/`, before the athlete ever reaches the tab-bar-having `/(app)` stack — consistent with the existing `(auth)/onboarding/` screens, which do not carry tab-bar clearance padding either.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 13px | 700 | 18px (1.38) |
| Body | 15px | 400 | 22px (1.47) |
| Heading | 18px | 700 | 24px (1.33) |
| Display | 28px | 700 | 32px (1.14) |

Exactly four sizes, exactly two weights, no exceptions: **400 (regular)** for all body/message text and celebration subcopy, **700 (bold)** for labels, headings, CTA button text, the mission-card eyebrow, and the celebration headline. Every text element in this phase's screens — including the mission card and the celebration overlay — maps onto one of the four rows above. There is no size or weight outside this table anywhere in this phase.

Accent reserved for: header avatar circle background, user-sent chat bubble background, the send button when input is non-empty, the mission card's CTA button background, the mission card's uppercase eyebrow label text, the celebration overlay's checkmark/avatar badge and its "Continuer" CTA button. **One documented exception:** the celebration overlay (only) uses a full dark hero background — `#1C1A17` with a soft `rgba(255,92,26,0.25)` radial glow — reusing `OBReady`'s exact treatment verbatim (D-15). This single full-screen "first win" moment deliberately breaks the 60/30/10 light-theme split, exactly as `OBReady`'s own "ready" screen already does, for the same reason: it is a deliberate, bounded, one-time reveal beat, not a routine screen. The Ziko chat screen itself (the conversational part) stays on the standard light 60/30/10 split — do not carry the dark treatment into the chat/question flow.

## Screen Layout Contract

Three distinct visual states, in flow order. All three inherit `theme.background`/`theme.surface`/`theme.border`/`theme.text`/`theme.muted`/`theme.primary` from `useThemeStore` (values above are the default-theme resolution, since a brand-new athlete has no coach branding override yet) — except the celebration overlay, which uses the fixed hardcoded hex values below (matching `OBReady`'s own hardcoded dark palette, not theme tokens).

**Visual focal point:** on the Ziko chat screen, the streaming assistant bubble is the primary visual anchor — it is the only element actively animating (typing/streaming) at any given moment, and its left-aligned, bordered surface against the plain `theme.background` gives it the strongest contrast weight on screen. The header avatar and input row are secondary; neither competes with the streaming bubble for attention. On the celebration overlay, the badge (checkmark icon) is the primary visual anchor, established first by its `FadeInUp` entrance and its shadow/glow treatment.

### 1. Ziko chat screen (`apps/mobile/app/(auth)/onboarding/ziko-chat.tsx`)

Direct structural reuse of `apps/mobile/app/(app)/ai/index.tsx` — same header/FlatList/input shape, with these explicit deltas:

**Outer container:** `paddingHorizontal: 24` (see Spacing Scale note above).

**Header** (`paddingHorizontal: 16, paddingVertical: 16` — the `md` token; adjusted from `ai/index.tsx`'s legacy `20px` horizontal value to conform to the declared spacing grid, see Spacing Scale note above; bottom border `theme.border`):
- 36×36 circle avatar, `theme.primary` (`#FF5C1A`) background, centered Ionicons glyph — use `happy-outline` (not `sparkles`, which is already the ongoing-coach's icon in `ai/index.tsx`) so Ziko reads as a visually distinct, separate identity per D-08.
- Title: "Ziko" (13px/700, `theme.text` — Label role) — no i18n key needed, it's a proper name, invariant across fr/en.
- Status line (13px/400 — Label size at Body weight): streaming → `"● " + t('coach.onboarding.thinking')` in green `#4CAF50` (reuses `ai.thinking`'s exact color/dot pattern); idle/awaiting reply → `"● " + t('coach.onboarding.online')` in `theme.muted`.
- **Remove entirely: the credit-balance chip (`⚡{balance}`) and the friends/community button.** Both are `ai/index.tsx`-only elements tied to the ongoing-chat credit economy and community plugin — this onboarding route is explicitly exempt from `creditCheck`/`creditDeduct` (see 43-RESEARCH.md Pitfall 2) and has no community context. Do not copy them over.

**Message list** (FlatList, `contentContainerStyle: { paddingVertical: 16 }`):
- Assistant bubbles: `theme.surface` background, 1px `theme.border`, `borderRadius: 18` with `borderBottomLeftRadius: 4`, `maxWidth: '85%'`, left-aligned, padding `16/8` (horizontal/vertical — `md`/`sm` tokens). Reuses `MessageBubble`/`renderMarkdown`/`MarkdownText` verbatim from `ai/index.tsx`, text at Body role (15px/400).
- User bubbles: `theme.primary` background, no border, `borderRadius: 18` with `borderBottomRightRadius: 4`, right-aligned, white text, same `16/8` padding, Body role.
- No per-bubble avatar — avatar appears only in the header and the celebration overlay, matching `ai/index.tsx`'s existing pattern exactly (do not introduce a new per-message-avatar treatment not present in the reused precedent).
- No `ListEmptyComponent` illustration/suggestion-chip state (that pattern belongs to the open-ended `/ai/chat`, not a scripted ≤4-question flow) — the screen always opens already-streaming Ziko's first question; see Copywriting Contract's "connecting" state for the brief pre-first-token gap.

**Input row** (unchanged shape from `ai/index.tsx`: `padding: 16`, top border, `theme.background` fill):
- `TextInput`: `theme.surface` background, `theme.border` 1px border, `borderRadius: 20`, `paddingHorizontal: 16 / paddingVertical: 8`, `fontSize: 15` (Body role), `maxHeight: 100`, multiline.
- Send button: 44×44, `borderRadius: 22`, filled `theme.primary` when input non-empty and not streaming, `theme.border` fill (disabled look) otherwise. Icon: `Ionicons name="send"`. Set `accessibilityLabel={t('coach.onboarding.sendA11y')}` (fr: "Envoyer", en: "Send") since the button is icon-only with no visible text label.
- **Remove the `{CREDIT_COSTS.chat}⚡` label inside the send button** — this onboarding route has no per-message credit cost; the button shows only the send icon, nothing else.

**Mission/summary card** (renders as the final assistant turn's content, not a modal or separate screen — inline within the last bubble, full chat-bubble-width `maxWidth: '92%'`):
- Container: `theme.surface` background, 1px `theme.border`, `borderRadius: 16`, `padding: 16`.
- Eyebrow label: 13px/700 (Label role), uppercase, `letterSpacing: 1`, color `theme.primary` — text `t('coach.onboarding.missionEyebrow')` ("TA PREMIÈRE MISSION" / "YOUR FIRST MISSION"). Reuses `OBReady`'s "Ton programme" eyebrow treatment, resized to the Label role's 13px (down from `OBReady`'s original 10px) for scale conformance.
- Mission title: 18px/700 (Heading role), `theme.text` — dynamic AI-generated one-line description of the specific micro-action (not a fixed string; Ziko phrases it in-voice).
- CTA button: full-width, `theme.primary` background, `borderRadius: 16`, `paddingVertical: 16`, white 15px/700 text, centered. Label is one of three fixed, i18n'd strings keyed to the tool's `micro_action` output (see Copywriting Contract) — never AI-generated, since it's a static UI control, not conversation content.
- Tapping the CTA deep-links via `router.push()` to the target plugin route and does **not** dismiss or replace the chat screen — the athlete returns to it (`useFocusEffect` re-poll per D-14) to trigger the celebration.

### 2. Celebration overlay (full-screen, presented over/replacing the chat screen once completion is detected)

Reuses `OBReady`'s exact visual treatment (D-15), hardcoded hex (not theme tokens):
- Full-screen `View`, `backgroundColor: '#1C1A17'`.
- Radial glow: absolutely positioned, `top: -40`, centered, 360×360, `borderRadius: 180`, `backgroundColor: 'rgba(255,92,26,0.25)'`, `pointerEvents="none"`.
- Badge: 76×76, `borderRadius: 22`, `#FF5C1A` background, centered Ionicons `checkmark` (size 38, white), matching `OBReady`'s check-icon shadow (`shadowColor: 'rgba(255,92,26,0.70)'`, `shadowRadius: 40`, `elevation: 16`). Entrance: `Animated.View entering={FadeInUp.springify().damping(12)}` — reused verbatim.
- Headline: 28px/700 (Display role), color `#FFFAF6`. No exception, no size/weight variant — this is the same Display row used everywhere else in this phase, just on the dark background. Dynamic content (athlete's name + which micro-action) composed from static i18n template + the completed action's label — see Copywriting Contract.
- Subcopy: 15px/400 (Body role), `rgba(255,250,246,0.70)`, `lineHeight: 22`.
- CTA: full-width, `#FF5C1A` background, `borderRadius: 16`, `paddingVertical: 16`, white 15px/700 text, `t('coach.onboarding.celebrationCta')` — on tap, `router.replace('/(app)')`.
- No skip/dismiss/back gesture — this overlay is a terminal step of the mandatory flow, same no-skip discipline as D-02.

### 3. Interaction/state notes for the executor

- No skip button, no back-navigation affordance anywhere in this flow (D-02) — the Expo Router stack for `(auth)/onboarding/ziko-chat` should disable swipe-back/hardware-back the same way the existing 7-step onboarding stack already does.
- Streaming indicator reuses the exact `ai/index.tsx` header-subtitle dot pattern — do not introduce a separate typing-indicator bubble/component.
- The mission card and celebration overlay must both render from **real, re-verified data** (D-14) — the celebration must never fire off a client-only "tapped the CTA" flag; it fires only after the `useFocusEffect` re-poll confirms a real row exists in the target log table for today.
