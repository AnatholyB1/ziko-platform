<objective>
Build the `assess_profile` backend tool: its JSON-Schema contract, its curated micro-action pool, its
`record_athlete_decision()` write call, and the `ONBOARDING_MAX_STEPS` step-cap constant that the
onboarding stream route (plan 43-03) consumes.

the schema, the mobile mission card (43-06) renders the chosen `micro_action`, and the retroactive path
(43-04) reuses the same state-patch shape. Defining it first removes ambiguity downstream.

Output: `backend/api/src/tools/onboarding.ts` (new), `ONBOARDING_MAX_STEPS` in `config/models.ts`,
executor registration in `tools/registry.ts`, and a unit spec.
</objective>

      p_user_id UUID, p_decision_type TEXT, p_week_of DATE, p_summary TEXT, p_rationale TEXT,

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model output → tool executor | LLM-generated `assess_profile` arguments cross into a privileged state write |
| backend → Postgres RPC | service-role client crosses into the only write path for athlete_state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-43-01 | Elevation of Privilege | assess_profile arguments | mitigate | Model cannot set `level`/`tier`/`points` at all — they are server-side constants `ONBOARDING_LEVEL`/`ONBOARDING_TIER`; only `readiness` is model-settable and is enum-constrained at both the JSON Schema and the DB CHECK layer |
| T-43-02 | Tampering | micro_action value | mitigate | Runtime membership check against `MICRO_ACTION_POOL` before the RPC call, in addition to the schema enum — the schema alone is not an enforcement boundary |
| T-43-03 | Repudiation | onboarding state write | mitigate | Every write journals to `athlete_decisions` with `p_source='onboarding_tool'` and non-null `p_evidence`; the RPC rejects a null/non-object evidence payload |
| T-43-04 | Elevation of Privilege | tool reachable from general chat | mitigate | `assessProfileSchema` deliberately excluded from `allToolSchemas` (Task 3), so `/ai/chat/stream` and `GET /ai/tools` never expose it |
| T-43-05 | Information Disclosure | assess_profile executor scope | mitigate | The executor scopes every RPC argument to the authenticated `userId` passed by the route; it accepts no user-id parameter from the model |
| T-43-SC | Tampering | npm/pip/cargo installs | accept | This plan installs zero packages (43-RESEARCH.md Package Legitimacy Audit: not applicable) |
</threat_model>
