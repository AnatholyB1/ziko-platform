<objective>
Close the mandatory-flow gate bypass (43-RESEARCH.md Pitfall 1), add the `coach.onboarding.*` i18n
namespace that the Ziko screens consume, and wire the lazy retroactive-recompute trigger for
pre-v1.18 athletes.

Purpose: today `apps/mobile/app/(auth)/_layout.tsx` redirects to `/(app)` on `profile.onboarding_done`
alone, and `step-7.tsx` sets that flag to `true` before the Ziko chat exists. An app kill mid-chat
would permanently skip the mandatory conversation, contradicting D-02 and leaving `athlete_state`
empty. This plan makes `athlete_state.status === 'active'` the second required gate condition before
any onboarding UI is written against it.

Output: extended i18n dictionaries, an `athleteOnboardingComplete` store field, a retroactive-recompute
client helper, and a corrected redirect gate.
</objective>
