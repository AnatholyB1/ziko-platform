<objective>
Build the pure semantics of the delta-aware verifier for D-09/D-10/D-11: frozen ziko vs portfolio, every table and every bucket, no sampling. PK subset is the presence gate, content digests catch silently altered rows, extra portfolio rows/objects are classified as explained (post-flip) or unexplained, tenant deltas follow D-11.

Purpose: DECOM-03. Strict count equality (`06-verify-data --check counts`) fails on any legitimate post-flip write (RESEARCH Pitfall 2), and PK presence alone would miss content drift, so a new evaluator set is needed. The CLI that runs these live plus the existing integrity/auth/tenant verifiers is plan 07-22 (split for context budget).
Discretion choice (D-09): delta explanations come from timestamp columns (created_at, updated_at) compared to backend_flip_at 2026-10-03T14:29:36Z from HANDOFF.json; tables without either column are reported `unexplained-needs-review` when portfolio has extra rows (fail), never silently passed. The uuid remap (1 known collision) is applied to ziko PK values and to ziko row content before comparison.
Output: 22-decom-verify.mjs (pure exports) + test.
</objective>

    - buildRowDigestSql({table, pkCols, sharedCols, flipAt, timestampCols, remap|null}) returns SQL producing (pk_key text, digest text, modified_after_flip boolean) per row: digest = md5 of the canonical jsonb text of the row restricted to sharedCols (`to_jsonb(t) - ARRAY[<non-shared cols>]`); when remap is given (ziko side) the source uuid text is replaced by the target uuid text before md5; modified_after_flip = greatest(created_at, updated_at) > flipAt over the timestamp columns that exist (false when none); throws on any non-IDENT table/column name or a remap value not matching the UUID shape.
    - evaluateContentDigest({table, source, target, hasTimestamps, countsEqual}) with source/target maps pk_key -> {digest, modified_after_flip}:
      - tables with created_at or updated_at: compares every shared PK whose portfolio row has modified_after_flip false; any digest difference fails with detail `content_mismatch=<n>`; rows skipped because modified after flip are counted as `skipped_post_flip=<n>` (pass). When the table has created_at but no updated_at, a mismatch still fails and the detail adds `no-updated_at` so 07-13 can classify it.
      - tables with neither column and countsEqual true: compares every shared PK; any difference fails.
      - tables with neither column and countsEqual false: content not compared; result ok with `limit: 'content-not-compared: no timestamp column and counts differ'` which buildDecomReport copies into `deviations` (the extras themselves already fail via classifyExtras).
      - detail strings never contain PK values or digests.
    - buildDecomReport -> shape {generated_at, target, source, flip_at, passed, tables:{total, pass, explained_extra, failed:[names]}, content:{compared_rows, skipped_post_flip, mismatched:[names], not_compared:[names]}, storage:{buckets, objects, missing, unexplained}, integrity:{rls, triggers, fk, orphans}, auth:{users, identities}, tenants:{data, storage, auth}, deviations:[]}; every content limit appears in deviations as {table, limit}; passes assertCommittedSafe; contains table and bucket names, counts and verdicts only.
