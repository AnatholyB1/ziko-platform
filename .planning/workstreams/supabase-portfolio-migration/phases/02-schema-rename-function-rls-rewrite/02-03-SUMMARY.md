# Phase 2 Plan 03: Dump-and-Rewrite Summary

**Two committed migrations recreate all 99 ziko tables and 33 functions under a ziko_ prefix, generated by a catalog-driven, rename-map-based rewrite tool; nothing has been applied to any database yet.**

## Accomplishments
- Schema migration: 1 sequence, 99 `CREATE TABLE public.ziko_*`, 381 constraints (FKs last), 117 standalone indexes, table and column privileges replicated from live ACLs, RLS enabled on all 99, 154 policies, 8 comments.
- Functions migration: `CREATE EXTENSION IF NOT EXISTS pg_net;` and `unaccent;`, 33 `CREATE OR REPLACE FUNCTION public.ziko_*`, grants, 18 public-schema triggers, and 22 function-dependent policies.
- `on_auth_user_created` and `on_auth_user_created_credits` (auth.users) are absent (D-02).
- The plan's stale-reference check passes: no `public.<old table>` in either file.

## Deviations from Plan

**1. [Rule 3 - Blocking] `supabase db dump` unusable.** It needs Docker (`LegacyDockerRunError`); there is no Docker or pg_dump here. The script instead reads pg_get_functiondef, pg_get_constraintdef, pg_get_indexdef, pg_get_triggerdef, pg_get_expr, pg_policies and aclexplode via `supabase db query --linked --file` (SELECT only). The statement splitter from the plan is not needed because the data is already structured. Commit 5951ed41.

**2. [Rule 2 - Missing critical] Standalone sequence `waitlist_founder_seq` is not in the rename map.** `ziko_claim_waitlist_signup` and `ziko_reset_waitlist_founder_sequence` reference it. The script discovers sequences live, creates `ziko_waitlist_founder_seq`, and rewrites references. The live value (87) is NOT carried over; Phase 3 data migration must `setval` it.

**3. [Rule 2 - Missing critical] Column-level ACLs.** `user_gamification.equipped_*` (4 columns) have UPDATE granted to `authenticated`. Table and column grants are replicated from live ACLs (REVOKE ALL then exact GRANTs), which also preserves table-level anon revokes.

**4. [Rule 1 - Bug] Ordering.** 22 policies call ziko functions (e.g. `ziko_is_coach_of`) and would fail in the schema migration, so they are created at the end of the functions migration. `SET check_function_bodies = off` wraps function creation.

**5. Other additions:** index and constraint names get a `ziko_` prefix (index names are schema-global and could collide with rh_*/gecko_* objects); table/function comments' `public.<name>` references are rewritten; search_path pin added to 11 functions that lacked one (the other 22 already had it).

## Items needing attention before apply (Plans 05/07)
- **X-Webhook-Secret placeholder:** `ziko_push_user_xp_level_up` / `push_workout_session_end` triggers contain `{{X_WEBHOOK_SECRET}}`; substitute the real value at apply time. Real value was never written to disk.
- **Event trigger `ensure_rls` not attached** (database-wide); only `ziko_rls_auto_enable()` is created.
- **Triggers call `supabase_functions.http_request`**; confirm the `supabase_functions` schema exists on portfolio.
- **CI risk:** `.github/workflows/ci.yml` auto-applies `supabase/migrations/` to ziko's own project on push to main. Merging these files to main would create `ziko_*` objects inside the live ziko DB. Plan 05/07 must apply via explicit project targeting, and `supabase db push` against portfolio will also see the 90 historical ziko migrations as unapplied; handle history explicitly.
- Files are not yet validated against a real Postgres (no local DB); Plan 05 scratch-project apply is the first execution test.
- Residual bare table-name tokens in output (4) are only inside string literals/comments (`'habits'` in a CHECK, SQL comments in `ziko_record_athlete_decision`); not identifiers.
