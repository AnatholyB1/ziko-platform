## Resolved at plan time — three corrections to the phase's own reference documents

These are implementation-shape choices, not one-way doors, so none of them takes a checkpoint. They
are recorded here because two of them contradict a snippet a downstream reader would otherwise copy.

**1. The coach pre-pick (D-08) is read on the client, not in the page component.**
`05-PATTERNS.md` says to read the role hint "in the page component and forward `preselected="coach"`
… as a plain prop threaded through server components, not client-side state". That instruction is
self-defeating: in Next 15 a page that awaits its request-time query object opts out of static
generation entirely, and WAIT-08 requires this route to stay static. The role hint is therefore read
inside `WaitlistRoleForm` with `useSearchParams()`, and the form subtree is wrapped in a `<Suspense>`
boundary so the surrounding page still prerenders. The route segment reads nothing at request time.

**2. The social preview is generated from code, not committed as a binary.**
`05-RESEARCH.md` and `05-UI-SPEC.md` both anticipate "a new `/og-fondateurs.png` asset", matching
`/og-coachs.png`. This plan instead uses the App Router's `opengraph-image` / `twitter-image` file
convention backed by `next/og`. Both satisfy ENTRY-04 identically, but the code route needs no image
tooling in the executor's sandbox, renders text with the framework's bundled font, is diffable in
review, is assertable in a unit test, and cannot drift from the page's own copy. `next` is already a
dependency; nothing new is installed.

**3. Localized copy is composed in the client from the action's structured fields.**
`claimWaitlistSpot` returns a French `message` string. That was correct for Phase 1, whose only
consumer was a Node test. This page is bilingual, so the rendered confirmation is derived from
`status` / `isFounder` / `founderRank` against the `fondateurs` message namespace, and `message` is
not rendered. This is also what keeps WAIT-06 structurally true rather than incidentally true: the
success panel branches on `isFounder` alone and has no knowledge of whether the row was new.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous visitor → `/fondateurs` | A fully public, unauthenticated page. Everything rendered here is world-readable and everything submitted here is attacker-controlled. |
| client form → `claimWaitlistSpot` Server Action | The one place visitor input crosses into server code and reaches a `SECURITY DEFINER` RPC. This plan builds the client half of that boundary; Plan 05-02 hardens the server half. |
| Phase 3's frozen legal module → rendered consent UI | The evidentiary chain behind `CONSENT_VERSION`. If the rendered text and the stored version identifier diverge, the consent record stops meaning anything. |
| build-time prerender → CDN | Page HTML is generated once and served to everyone. Anything visitor-specific baked in here leaks to every visitor. |
