# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled Tailwind v4 + Framer Motion components, the house pattern used by every existing `apps/web/src/components/marketing/*` file (`Hero.tsx`/`HeroClient.tsx`, `CoachsHeroClient.tsx`, `CoachsFeatureBlocksClient.tsx`, `CoachsCtaFooterClient.tsx`) |
| Icon library | `react-icons/io5` (Ionicons set) — confirmed in `HeroClient.tsx` (`IoChevronDownOutline`) and `CoachsFeatureBlocksClient.tsx` (`IoPeopleOutline`, `IoSparklesOutline`, `IoCalendarOutline`, `IoRocketOutline`) |
| Font | Inter (`next/font/google`, `apps/web/src/app/[locale]/layout.tsx`) |

**Assumption recorded — shadcn gate skipped by design, not by omission.** This is a `--auto` chained run
(discuss → plan → execute, no interactive prompts). `components.json` does not exist anywhere in the
repo, and `apps/web` already has a mature, internally consistent, **non-shadcn** design system: Tailwind
v4 `@theme` tokens in `globals.css` (`--color-primary`, `--color-background`, `--color-text`,
`--color-border`, `--color-muted`, plus semantic status colors), and every one of the 15+ existing
marketing/account components is a hand-rolled Tailwind component using that token set directly (no Radix,
no Base UI, no shadcn primitives anywhere in `apps/web/src`). Initializing shadcn now, for one phase,
would fragment the design system rather than serve WAIT-07's explicit requirement to "match the existing
light sport theme and Tailwind v4 tokens." **Decision: Phase 5 follows the established house pattern —
hand-rolled Tailwind components, no shadcn.** Registry safety gate is therefore not applicable (see
Registry Safety below).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, badge internal spacing |
| sm | 8px | Compact element spacing (form field label-to-input gap) |
| md | 16px | Default element spacing (card internal gaps, form field vertical rhythm) |
| lg | 24px | Sub-section padding (role-picker card padding, form container padding on mobile) |
| xl | 32px | Page horizontal padding (`px-8`, matches every existing marketing page's `max-w-screen-xl mx-auto px-8` shell) |
| 2xl | 48px | Gap between major page blocks (hero → role picker → counter → legal footer) |
| 3xl | 64px | Reserved, not used at this scale in Phase 5 |
| 4xl | 80px (`py-20`) | Hero-region vertical padding — matches `HeroClient.tsx`/`CoachsHeroClient.tsx` exactly, used twice (page hero, homepage founders-section hero-style intro) |
| 5xl | 96px (`py-24`) | Standard marketing-section vertical padding — matches `CoachsFeatureBlocksClient.tsx`/`CoachsCtaFooterClient.tsx` exactly, used twice (role-picker section, counter/legal section) |

Both 4xl and 5xl are multiples of 4px and are not new — they are the exact values every existing marketing
section on this site already uses; Phase 5 does not introduce a new spacing idiom, only names the
already-established values so they're part of the formal scale rather than implicit exceptions.

Touch-target exception (not a spacing-scale token, a minimum-hit-area rule):
- `min-h-[44px]` — required on the new header/footer "Fondateurs" nav link and the two role-picker
  cards, matching `HeaderClient.tsx`'s existing locale-switcher links (`min-h-[44px] inline-flex items-center`).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (page H1, `/fondateurs` hero headline) | 48px mobile / 72px desktop (`text-5xl md:text-7xl`) | Bold (700) | 1.05 (`leading-none`) |
| Heading (section headings — homepage founders section, role-picker section title, complete-state heading) | 30px mobile / 36px desktop (`text-3xl md:text-4xl`) | Bold (700) | 1.2 |
| Body (subheadline, form labels expanded, consent copy, collection notice, success/error message body) | 16px (`text-base`) | Regular (400) | 1.5 |
| Label (nav link, form field label, offer badge/pill text, legal microcopy, counter caption, button text) | 14px (`text-sm`) | Regular (400) for static labels / legal microcopy / Bold (700) for button, badge, and counter-emphasis text | 1.4 |

Exactly 4 sizes declared, no exceptions: **Display, Heading, Body, Label.** Exactly 2 weights declared:
**Regular (400)** and **Bold (700)**.

**Documented deviation:** `Hero.tsx`/`CoachsHeroClient.tsx` use `font-black` (900) for their H1. Phase 5's
Display role uses Bold (700) instead — a deliberate simplification to respect this contract's 2-weight
cap. This does not violate WAIT-07 (colors, tokens, spacing, and component idiom are unchanged); only the
single heaviest weight is normalized down one step.

**Documented deviation:** the offer badge/pill text and legal microcopy (`ctaNote`) are rendered at
`text-xs` (12px) elsewhere on this site (`HeroClient.tsx`, `CoachsCtaFooterClient.tsx`). Phase 5
normalizes both up to the Label size, 14px (`text-sm`), instead of introducing a fifth font size — the
badge keeps its `font-bold` weight, legal microcopy stays `font-normal text-muted`. See Component
Specifications §4 for the updated badge classes.

## Component Specifications

> Resolves the two open design questions RESEARCH.md flagged explicitly (Assumption A2 / Open Question 1,
> and D-10's "concrete visual treatment" note). Auto-mode calls, made from CONTEXT.md's decisions and
> existing codebase idiom — not asked interactively.

### Focal points

- **`/fondateurs` page:** the primary visual anchor is the **role-picker card pair** (§3 below), not the
  hero headline or the offer badge. The hero establishes the offer in one line and then hands off
  immediately — the two role cards are the largest, highest-contrast interactive elements above the fold,
  and the accent color's first live use on the page is the card's selected-state border/badge. Offer copy
  and the counter badge are supporting context that justifies the action, not the thing the eye lands on.
- **Homepage founders section:** the primary visual anchor is the **CTA button** (`bg-primary`,
  "Devenir fondateur →"), consistent with every other homepage section on this site ending in a single
  primary-accent action. The counter/offer copy sits above it as justification, matching the section's
  role as a teaser that routes to `/fondateurs` rather than a duplicate of the full role-picker flow.

### 1. ENTRY-03 header treatment — plain nav link placement

`HeaderClient.tsx`'s current row is `Logo | [locale FR|EN] [primary CTA button]` inside a single
non-wrapping `flex items-center justify-between` container. D-03 keeps the CTA button unchanged
(→ `/coach/dashboard`); D-04 requires the new founders link to carry the same visual weight as the locale
switcher, not a pill.

**Decision:** Insert the new **"Fondateurs" / "Founders"** link as a plain text link **between the logo
and the locale switcher** (left of `FR | EN`), using the exact same class recipe as the *unselected*
locale link state: `text-sm text-muted hover:text-text transition-colors px-2 py-2 min-h-[44px] inline-flex items-center rounded`.
The right-hand wrapper (`<div className="flex items-center gap-4">`) gets `flex-wrap justify-end gap-y-2`
added so that on very narrow viewports (where logo + nav link + locale switcher + CTA button cannot fit
on one line) the row wraps to a second line instead of clipping or forcing horizontal scroll — no new
hamburger/mobile-nav component is introduced, consistent with this header never having had one. Resulting
order, left to right, wrapping as needed: `Logo | Fondateurs | FR|EN | [CTA button]`.

### 2. FooterClient.tsx nav link

Add `<AnimatedLink href="/fondateurs">{founders}</AnimatedLink>` into the existing `<nav>` list in
`FooterClient.tsx`, positioned first (before "Mentions légales"), using the existing `AnimatedLink`
helper verbatim — zero new styling code, matches D-04's "same visual weight as `Mentions légales`, `CGU`,
`CGV`" requirement exactly.

### 3. Role-picker cards (WAIT-02, D-08)

Two cards, side by side on `md:` and up (`grid grid-cols-1 md:grid-cols-2 gap-4`), stacked on mobile.
Visual recipe matches `CoachsFeatureBlocksClient.tsx`'s existing card pattern, made interactive:

- **Unselected:** `bg-white border border-border rounded-2xl p-6` (use `lg` token, 24px, not the
  feature-block's `p-8` — this card holds less content), icon circle `w-12 h-12 rounded-full bg-primary/10`
  with an `IoBarbellOutline` (athlete) / `IoPeopleOutline` (coach) icon at `text-primary`, label below at
  Heading-adjacent weight (`text-lg font-bold text-text`).
- **Selected:** `border-2 border-primary bg-primary/5`, plus a small `IoCheckmarkCircle` badge
  (`text-primary`, top-right corner) — the only accent-color state change on the card.
- **Interaction:** clicking a card sets the picked role and reveals the email field directly below the
  card grid with a `fadeUp` transition (reuse `apps/web/src/lib/motion.ts`'s existing `fadeUp` variant —
  no new animation primitive). Cards remain clickable/togglable after a role is picked (D-08 — "still
  changeable"), including when the page loads with coach pre-picked via the `/coachs` redirect.

### 4. Counter/offer badge widget (FOND-01/02/05, D-10)

One widget, three mutually exclusive visual states, all built on the badge shape already established by
`HeroClient.tsx`'s existing badge span, with the text size normalized up to this contract's Label size
(`inline-flex ... text-sm font-bold px-4 py-2 rounded-full border` — `text-sm`, not `HeroClient.tsx`'s
original `text-xs`, per the Typography section's documented deviation):

| State | Classes | Content |
|-------|---------|---------|
| Pre-threshold (`should_display: false`) | `bg-primary/10 text-primary border border-primary/20` | Static fact copy — see Copywriting Contract "Empty state — pre-threshold counter" |
| Counter visible (`should_display: true, is_full: false`) | `bg-primary/10 text-primary border border-primary/20` (unchanged shape) | Live "Plus que N places" copy, `{remaining}` bold-emphasized within the badge text |
| Complete (`is_full: true`) | `bg-surface-alt text-muted border border-border` — **primary accent deliberately absent**, per the color contract's accent-reserved-for list | `IoCheckmarkDoneOutline` icon (`text-muted`) + the D-10 heading/body copy rendered as a small card below the badge (`bg-white border border-border rounded-xl p-4`), not just badge text — this is the "distinct state change" D-10 calls for, not a same-shape badge with different words |

Loading state (while `/api/waitlist/count` resolves): render the pre-threshold badge shape with a
`fadeIn`-animated pulse/skeleton fill instead of text — never blank space, never layout shift, resolved
before the real response arrives (typically instant given the Route Handler's `revalidate: 30`).

Fetch-error fallback: if the Route Handler returns its documented safe-default payload
(`{ shouldDisplay: false, remaining: null, isFull: false }`, per `05-RESEARCH.md` Pattern 3), the UI
renders the pre-threshold state — never a broken/undefined badge, never a raw error message shown to a
visitor.

### 5. Success / inline confirmation panel (WAIT-05/06)

Replaces the form in place (matches `DeleteAccountForm.tsx`'s existing success-swap pattern:
`bg-success-subtle border border-success/30 rounded-lg p-6`), reusing that exact card recipe with the
Copywriting Contract's success-state text. No confetti/celebratory animation beyond the existing
`fadeUp` entrance — keeps scope minimal and consistent with the rest of the site's restrained motion
language.
