## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| manifest file → the delete loop | The manifest is the authorization artifact for an irreversible cascade; whoever edits it chooses who gets deleted |
| CLI flags → destructive execution | A single flag separates an inert run from a production cascade |
| service-role client → `auth.users` | The Admin API bypasses every RLS policy and fans out through 31 `ON DELETE CASCADE` chains |
| post-purge database state → the verification claim | A scan that fails open would certify a purge that actually left orphans |
