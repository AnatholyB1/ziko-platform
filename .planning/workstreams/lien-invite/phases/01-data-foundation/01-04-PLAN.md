<objective>
Prove the two properties this phase is named for, both through the path production actually takes:
that the 200-founder cap is exact when submissions race across the boundary, and that re-submitting
somebody else's address never tells you whether they hold a founder spot. Then wire both proof
suites into CI behind the test project, with the migration actually applied first.

Purpose: the cap is an engine-level guarantee that only a real race can confirm, and the
non-disclosure filter lives in the Server Action, so an assertion against the RPC would prove
nothing about what an attacker can observe. Wiring them into `test-rls.yml` closes the gap the
researcher found: that workflow has no migration-apply step, so a suite could otherwise pass
against a schema that predates the change under review.

Output: the concurrency and non-disclosure blocks in
`apps/web/test/actions/waitlist.concurrency.test.ts`, and a `.github/workflows/test-rls.yml` that
applies the migration to the test project and runs both suites.
</objective>
