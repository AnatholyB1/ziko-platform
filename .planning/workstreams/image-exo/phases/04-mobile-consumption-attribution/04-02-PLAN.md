## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Supabase Postgres (`public.exercises`, RLS-protected) → mobile client | Row data crosses here. The SELECT policy `is_custom = FALSE OR user_id = auth.uid()` (migration `001_initial_schema.sql:293`) is pre-existing and unchanged by this plan. |
| Supabase Storage (`exercise-media`, public-read) → mobile client | Thumbnail bytes cross here. Public-read by design (MEDIA-02, Phase 1); no client INSERT/UPDATE/DELETE policy exists. |

This plan introduces no new boundary — it adds one column to an existing, already-authorized SELECT and renders it.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `ex.image` value passed to `getPublicUrl()` in ExercisePicker.tsx | accept | Not exploitable: `exercises.image` is written exclusively by the service-role Phase 3 merge script, whose `storagePaths()` derives the path from the exercise UUID only, never from dataset text. The `exercise-media` bucket has no client write policy, so no user can plant a path. Matches 04-RESEARCH.md Security Domain (ASVS V5 rated "marginal / not exploitable" for this phase). |
| T-04-02 | Information Disclosure | Adding `image` to the picker's `select()` | accept | `image` is a non-sensitive relative Storage path to a public-read asset; the rows returned are already gated by the pre-existing RLS SELECT policy, which this plan does not modify. |
| T-04-SC | Tampering | npm/pip/cargo installs | n/a | Zero packages installed (04-RESEARCH.md "Package Legitimacy Audit: Not applicable"). `expo-image` is a pre-existing `apps/mobile` dependency at `~3.0.11`; no `package.json` edit is permitted in this plan. |
