## Spacing Scale

Project already declares a spacing scale in `packages/ui/src/components.tsx` — reuse it verbatim, do not invent new values:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside badges |
| sm | 8px | Attribution badge padding, compact gaps |
| md | 16px | Screen horizontal padding, default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| xxl | 48px | Major section breaks |

Exceptions:
- `ExercisePicker` row gap and checkbox size (22×22, `borderRadius: 6`) are pre-existing non-4pt values in the touched file — **do not change them**, only insert the new 40×40 thumbnail alongside them using the row's existing `gap: 12` (already a project value, kept for consistency rather than forced onto the packages/ui scale).
- Attribution badge corner offset uses `8px` (spacing.sm) from both edges — see Component Specifications.

## Component Specifications

### 1. Hero Media Card (`[exerciseId].tsx`, replaces the 16:9 placeholder at lines ~200–297)

Structural container:
```
width: 100% (fills the screen's existing 16px horizontal padding, i.e. screen width − 32)
aspectRatio: 1            // square, replaces aspectRatio: 16/9
borderRadius: 14          // unchanged from current card
overflow: hidden
backgroundColor: theme.surface   // #FFFFFF — was #1C1A17 (fake video chrome removed per D-02)
borderWidth: 1
borderColor: theme.border
shadowColor: theme.text
shadowOpacity: 0.08
shadowRadius: 12
shadowOffset: { width: 0, height: 2 }
elevation: 3
```
This exactly matches the shadow/border convention already used by the stat tiles and tab-content cards lower on the same screen (lines ~302–316) — the hero now looks like a card, not a video frame.

Media (happy path — `exercise.gif` present):
```tsx
<Image
  source={{ uri: publicGifUrl }}   // supabase.storage.from('exercise-media').getPublicUrl(exercise.gif).data.publicUrl
  style={{ width: '100%', height: '100%' }}
  contentFit="cover"
  transition={150}
/>
```
No play button, no "HD" badge, no "Démo · 0:42" text — all chrome from the old placeholder is deleted (D-02). No static thumbnail-then-tap state — the GIF always renders animating (D-03).

Wrap this whole block in `<AttributedMedia>` (see §2) with `showBadge` on — this is the phase's one and only badge instance (D-05).

Missing-media path (`exercise.gif` is null — see §4 for the shared placeholder spec): same square slot, same border/shadow, centered `barbell-outline` icon at 48px, no `<AttributedMedia>` badge rendered (D-07 — nothing to credit).

### 2. `<AttributedMedia>` component (new, `packages/ui/src/components/AttributedMedia.tsx`)

Purpose: structurally enforce MOBILE-03 — every consumer that renders Gym visual media through this component gets the credit badge and the 180×180 display cap without having to remember to add either.

```ts
interface AttributedMediaProps {
  uri: string | null;           // full public Storage URL, or null → renders the fallback
  size?: number;                 // default 180 — hard display cap, component ignores larger values
  borderRadius?: number;         // default 14
  showBadge?: boolean;           // default true — set false for any future non-primary instance
  credit?: string;                // default '© Gym visual — https://gymvisual.com/', do not override the text, only the boolean
  fallbackIconSize?: number;     // default 48
}
```
Behavior contract:
- `size` is clamped: `Math.min(size ?? 180, 180)` — the component itself refuses to render above 180×180 regardless of what a caller passes, satisfying the "structurally enforces the cap" requirement text.
- When `uri` is falsy, renders the shared missing-media placeholder (§4) instead of an `<Image>`, and never renders the badge.
- Badge only mounts when `showBadge && uri` are both true.

Badge visual spec (locked pixel values — this is the concrete answer to CONTEXT.md's "exact corner/opacity/typography" discretion item):
```
position: absolute
bottom: 8            // spacing.sm
right: 8              // spacing.sm — mirrors where the old "HD" badge sat (D-04)
paddingHorizontal: 8
paddingVertical: 3
borderRadius: 6       // rounded rect, not a full pill — the credit string is long, a pill reads oddly at this length
backgroundColor: 'rgba(28,26,23,0.55)'   // theme.cardDark at 55% — dark-neutral overlay reads on any underlying image color, matches the "semi-transparent" instruction in D-04
```
Text:
```
fontSize: 9
fontWeight: '600'
color: '#FFFAF6'      // theme.cardDarkText
letterSpacing: 0
numberOfLines: 1
```
Content: exactly `© Gym visual — https://gymvisual.com/` — no shortening, no line-wrap.

Usage on the detail screen: `<AttributedMedia uri={publicGifUrl} size={hero card's rendered width} showBadge />` wrapping the hero (§1). `ExercisePicker` thumbnails do **not** use this component (see §3 — this is D-06, a deliberate, discussed narrowing of MOBILE-03's literal wording, not an oversight).

### 3. `ExercisePicker` row thumbnail (new, inserted before the checkbox at line ~273)

```
width: 40
height: 40
borderRadius: 10
flexShrink: 0
overflow: hidden
```
Positioned as the **first** child in the row's existing `flexDirection: 'row', gap: 12` container — thumbnail → checkbox (22×22, unchanged) → info block (unchanged), each separated by the row's existing 12px gap. No new gap token introduced.

Image (happy path — `ex.image` present):
```tsx
<Image
  source={{ uri: publicThumbUrl }}   // supabase.storage.from('exercise-media').getPublicUrl(ex.image).data.publicUrl
  style={{ width: 40, height: 40, borderRadius: 10 }}
  contentFit="cover"
/>
```
Uses the static `thumb.png` (the `image` column), **never** the animated `gif` column — list rows must not auto-animate (locked in D-09).

No `<AttributedMedia>` wrapper and no badge here — per D-06, attribution renders once per screen on the primary hero only.

### 4. Missing-media placeholder (shared visual, two sizes)

Icon: `barbell-outline` (Ionicons) — neutral, fitness-relevant, reads clearly at both sizes. Used by `<AttributedMedia>`'s internal fallback (hero) and directly inline in `ExercisePicker` (thumbnail, since thumbnails bypass `AttributedMedia` entirely per D-06).

Hero size (inside the 1:1 card from §1):
```
Icon: barbell-outline, size 48, color theme.muted (#6B6963)
Container: fills the full square slot, centered (alignItems/justifyContent: 'center')
Background: theme.surface (inherits the card's existing background — no separate fill needed)
Optional caption below icon: "Aperçu indisponible" / "Preview unavailable", fontSize 11, color theme.muted, marginTop 6
```
List-row thumbnail size (40×40 slot):
```
Icon: barbell-outline, size 18, color theme.muted (#6B6963)
Container: width 40, height 40, borderRadius 10, alignItems/justifyContent: 'center'
Background: theme.background (#F7F6F3) — distinguishes the empty slot from the white row background
Border: 1px solid theme.border — gives the empty square definition against the card's own border
```
Row layout stays uniform whether or not a thumbnail exists — same slot, same size, same position (D-08).

### 5. Instructions numbered steps (`[exerciseId].tsx`, Consignes tab, replaces the `cues` fallback chain at lines ~125–136)

No new visual component — the existing numbered-circle row style (lines ~490–513: 22×22 circle, `rgba(255,92,26,0.14)` fill, `#FF5C1A` number text, 12px/18px body text) is kept exactly as-is and now sources its array directly from `instruction_steps[locale] ?? instruction_steps.en` instead of the `JSON.parse`/`.split('\n')` chain. Locale selection follows the existing `tExercise`-style pattern (`plugin-sdk/src/i18n.ts`) — `fr` array when locale is `fr`, `en` array otherwise, per MOBILE-05.

When both `instruction_steps` and the legacy `instructions`/`instructions_fr` TEXT columns are empty (the 6 unmatched-new rows before any backfill), render the `EmptyState` component (`packages/ui`, variant `'no-data'`) inside the Consignes tab's existing card shell instead of an empty numbered list — see Copywriting Contract for the exact copy.
