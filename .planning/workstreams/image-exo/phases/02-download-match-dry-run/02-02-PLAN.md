## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream GitHub dataset → pipeline memory | Untrusted third-party JSON is parsed and its string fields are later joined into filesystem paths |
| script process → Supabase Postgres | Credentialed access to production data crosses here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `DatasetExerciseSchema` in `lib/types.ts` | mitigate | zod validation of every dataset record before it reaches any consumer; `image`/`gif_url` carry the upstream `^images/.+\.(jpg\|jpeg\|png)$` / `^videos/.+\.gif$` regexes, which reject `../` traversal payloads at parse time. Tested explicitly with an `../../etc/passwd` fixture (Task 1). Consumers get a loud `ZodError`, never an undefined field. |
| T-02-02 | Elevation of Privilege | `lib/supabase-client.ts` | mitigate | Publishable key only — `SUPABASE_SERVICE_KEY` is grep-asserted absent from the file. Read scoping is delegated to the existing `read_exercises` RLS policy rather than app-level filtering (ASVS V4, least privilege). |
| T-02-03 | Tampering | write surface of the dry-run pipeline | mitigate | Automated test asserts `insert`/`update`/`upsert`/`delete`/`rpc` are never invoked on the client, and a grep gate asserts those call sites do not exist in source (roadmap SC #4) |
| T-02-05 | Denial of Service | production read path | accept | A full-table paginated read of ~1,300 rows against a hosted Supabase project is negligible load, and this is a manually-invoked developer script with no automated schedule |
</threat_model>
