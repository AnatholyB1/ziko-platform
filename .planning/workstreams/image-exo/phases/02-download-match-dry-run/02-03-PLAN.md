<objective>
Implement IMPORT-01: fetch the dataset via `git clone --depth 1` (cached and reusable), then verify it against its manifest-equivalent and fail loudly on any mismatch, writing nothing to the database.

Purpose: `hasaneyldrm/exercises-dataset` has NO literal manifest file (verified via the GitHub API in 02-RESEARCH.md — `data/` contains only `exercises.json` and `exercises.schema.json`). This plan resolves that requirement-wording gap explicitly: `exercises.json`'s own array IS the manifest — its length must equal the file count in `images/` and in `videos/`, and every record's `image`/`gif_url` path must resolve to a real file inside the dataset root.
Output: `lib/verify.ts` (pure, unit-tested) and `fetch.ts` (thin entrypoint).
</objective>

    Create `lib/verify.ts` — pure functions only, every path taken as a parameter so tests can
    point them at a fixture tree. No `__dirname`, no `import.meta.url`.

    Export:
    - `resolveInsideRoot(datasetRoot: string, relativePath: string): string | null` — joins and
      `path.resolve`s the two, then returns the absolute path ONLY if it is still contained
      within `path.resolve(datasetRoot)` (compare with a trailing-separator-aware prefix check,
      not a bare `startsWith` on the raw string). Returns `null` for anything that escapes.
      This is the defence-in-depth layer behind the zod path regexes: even if a regex were
      loosened later, a crafted `image` value can never cause a read outside the clone.
    - `loadDatasetJson(jsonPath: string): DatasetExercise[]` — `readFileSync` + `JSON.parse` +
      `DatasetExerciseArraySchema.parse`. Let the `ZodError` propagate — upstream schema drift
      must be loud (IMPORT-01 "failing loudly").
    - `verifyDataset(datasetRoot: string): string[]` — returns an array of human-readable
      mismatch strings (empty array = verified). It must check, in this order:
      1. `data/exercises.json`, `images/`, and `videos/` all exist under `datasetRoot` —
         otherwise return a single "dataset structure missing" mismatch and stop
      2. `readdirSync(images/).length === records.length` — mismatch string names both numbers
      3. `readdirSync(videos/).length === records.length` — mismatch string names both numbers
      4. for every record: `resolveInsideRoot(datasetRoot, record.image)` is non-null and the
         file exists; same for `record.gif_url`. Mismatch strings include the record `id` and
         the offending path. A `null` from `resolveInsideRoot` produces a distinct
         "path escapes dataset root" mismatch string containing the word `escapes`.
      5. duplicate `id` detection across records — a duplicate dataset id would silently
         collapse rows in the matcher's index later
      Cap the emitted per-record mismatch list at the first 25 entries plus a
      "...and N more" line, so a totally-wrong clone does not print 1,324 lines.

    Create `lib/verify.test.ts` building small temp fixture trees with `fs.mkdtempSync` under
    `os.tmpdir()` (created and torn down inside the test — never touching the real cache dir).
    Cover: a well-formed 2-record fixture returns `[]`; an images/ dir with one extra file
    returns a mismatch naming both counts; a record pointing at a nonexistent image returns a
    mismatch containing that record's id; a record with `image: '../../../etc/passwd'` returns a
    mismatch containing `escapes` (construct this fixture by writing the JSON directly and
    bypassing zod, or by asserting `resolveInsideRoot` returns null for it — both paths must be
    covered); duplicate ids are reported; a missing `videos/` directory returns the structural
    mismatch; `loadDatasetJson` on a file missing a required field throws `ZodError`.
  </action>

    Create `fetch.ts` as a thin entrypoint. It is run only via
    `npx tsx scripts/exercise-import/fetch.ts` from the repo root and is NEVER imported by a
    test, so it may call `main()` unconditionally at module load (this is what keeps the
    CommonJS/ESM `import.meta.url` problem out of the codebase entirely).

    Behaviour, in order:
    1. `assertRunFromRepoRoot()` first — fail with a clear message if cwd is wrong
    2. Parse `process.argv` for a `--refetch` flag (no argument-parsing library; a
       `process.argv.includes('--refetch')` check is sufficient)
    3. Clone-or-reuse (resolves D-12): if `DATASET_ROOT` already exists and `--refetch` was not
       passed, print that the cached clone is being reused and skip the network entirely
       (the working tree is ~128MB; the matcher will be re-run many times during threshold
       tuning). If `--refetch` was passed, `rmSync(DATASET_CACHE_DIR, { recursive: true, force: true })`
       first. Then `mkdirSync(DATASET_CACHE_DIR, { recursive: true })` and clone with
       `spawnSync('git', ['clone', '--depth', '1', DATASET_REPO_URL, DATASET_ROOT], { stdio: 'inherit' })`.
       Use the argv-array form of spawnSync — never string interpolation into a shell — and
       treat a non-zero `status` or a non-null `error` as a hard failure. `--depth 1` is
       mandated by IMPORT-01, it is not a tuning choice.
    4. Record the cloned commit SHA via
       `spawnSync('git', ['-C', DATASET_ROOT, 'rev-parse', 'HEAD'], { encoding: 'utf-8' })` and
       print it — plan 02-05 stamps this into the report's `dataset_commit` field, so print it
       in a machine-greppable single-line form (e.g. `dataset_commit=<sha>`).
    5. `loadDatasetJson(DATASET_JSON_PATH)` — a `ZodError` here means upstream drift; catch it
       and re-print it as a clearly-labelled schema-drift failure before exiting non-zero
    6. `verifyDataset(DATASET_ROOT)` — if the returned array is non-empty, print
       `MANIFEST VERIFICATION FAILED:` followed by each mismatch on its own line and
       `process.exit(1)` immediately. This is D-11: a hard exit with NO report written. Do not
       emit a partial or warning-stamped artifact.
    7. On success, print a summary: record count, images/ count, videos/ count, the commit SHA,
       and the next command to run (`npx tsx --env-file=backend/api/.env.local scripts/exercise-import/match.ts`)

    This file must never import `@supabase/supabase-js` and must never read Supabase env vars —
    fetch is a pure filesystem/network step.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| github.com → local filesystem | An arbitrary third-party working tree is written to disk and its contents are trusted as data |
| dataset JSON string fields → filesystem path joins | `record.image` / `record.gif_url` are attacker-controllable strings used to build read paths |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `lib/verify.ts` path handling | mitigate | Two independent layers: (a) `DatasetExerciseSchema`'s `^images/.+\.(jpg\|jpeg\|png)$` and `^videos/.+\.gif$` regexes reject traversal at parse time; (b) `resolveInsideRoot()` re-checks containment after `path.resolve` and returns `null` on escape. Both are unit-tested with an `../../../etc/passwd` fixture. |
| T-02-06 | Tampering | upstream schema drift between research (2026-08-15) and execution | mitigate | `loadDatasetJson` parses through zod on every run and surfaces a labelled schema-drift failure with a non-zero exit — today's verified schema is never treated as permanently locked in |
| T-02-07 | Tampering | `git clone` invocation | mitigate | `spawnSync` with an argv array and no `shell: true`; the repo URL is a hardcoded constant in `lib/paths.ts`, never built from user input. Grep gate asserts `execSync` and `shell: true` are absent. |
| T-02-04 | Information Disclosure | cloned working tree in git history | mitigate | Clone target is `scripts/exercise-import/.dataset-cache/`, gitignored in plan 02-01 and verified with `git check-ignore` |
| T-02-02 | Elevation of Privilege | fetch.ts credentials | mitigate | fetch.ts imports no Supabase client and reads no Supabase env var — grep-asserted. There is no credential to escalate. |
| T-02-08 | Denial of Service | repeated 128MB clones | accept | Clone-reuse (D-12) makes repeat runs free; a manually-invoked developer script re-downloading on `--refetch` is intended behaviour |
</threat_model>
