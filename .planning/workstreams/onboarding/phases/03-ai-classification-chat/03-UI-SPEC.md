Phase 3 appends messages to the existing `<div className="flex flex-col gap-3 mb-6">` container from Phase 2. It never replaces or re-renders the Phase 2 opening bubble.

### 2. IA Bubble (canonical — matches Phase 2 exactly)

<div class="bg-surface-alt rounded-xl rounded-tl-none px-4 py-3 text-sm text-text max-w-xs">

Source: 02-CONTEXT.md, confirmed in WizardStep4Import.tsx line 337.

### 3. IA Chat Row Container (canonical)

```html
<div class="flex items-start gap-2">
  {IA avatar}
  {IA bubble}
</div>
```

### 4. Coach Reply Bubble (NEW — right-aligned, no avatar)

```html
<div class="flex justify-end">
  <div class="bg-primary/10 rounded-xl rounded-tr-none px-4 py-3 text-sm text-text max-w-xs">

  </div>
</div>
```

Design rationale: mirrored from IA bubble — uses `rounded-tr-none` (vs `rounded-tl-none`), `bg-primary/10` (10% primary tint) to distinguish coach voice from IA surface-alt. No avatar — right-alignment is the signal. `justify-end` on the row wrapper.

### 5. Clarification Pills (inline inside IA bubble)

Pills render as children of the IA bubble div, below the question text.

```html
<div class="bg-surface-alt rounded-xl rounded-tl-none px-4 py-3 text-sm text-text max-w-xs">
  {t('step4AiAmbiguous', { filename })}
  <div class="flex gap-2 mt-3 flex-wrap">
    <button
      type="button"
      onClick={() => handleClarification(fileId, 'template_programme')}
      class="px-3 py-2 rounded-full border border-border text-sm font-bold text-text
             hover:border-primary hover:text-primary transition-colors"
    >
      {t('step4PillTemplate')}
    </button>
    <button
      type="button"
      onClick={() => handleClarification(fileId, 'da_coach')}
      class="px-3 py-2 rounded-full border border-border text-sm font-bold text-text
             hover:border-primary hover:text-primary transition-colors"
    >
      {t('step4PillDaCoach')}
    </button>
  </div>
</div>
```

- Pill shape: `rounded-full` (capsule)
- Pill default: `border border-border text-text bg-transparent`
- Pill hover: `hover:border-primary hover:text-primary` (no fill — border + text color shift)
- Pill size: `px-3 py-2` — 12px horizontal, 8px vertical (touch-friendly at 32px height)
- After selection: pills are removed from DOM; replaced by coach reply bubble

### 6. docType Badge (on file card row — BOTH locations)

Display on the file card row **and** inferred from the summary bubble copy. The badge appears on the file card immediately after `docType` is set.

```html
<!-- Inside file card row, between StatusPill and remove button -->
<span class="inline-flex items-center px-2 py-1 rounded-md text-xs font-bold bg-surface-alt text-text border border-border">
  {docType === 'template_programme' ? t('step4DocTypeTemplate') : t('step4DocTypeDaCoach')}
</span>
```

- Badge appears: immediately when `docType` is set (auto-classified or coach-resolved)
- Badge does NOT appear during `uploading` or `parsing` — only after `ready` + classification
- Failed files: no badge (no `docType` to show)

### 7. "Continuer →" Primary CTA Button (NEW)

Appears at the bottom of the card in the existing button row, to the left of "Ignorer pour l'instant", when the advance condition is met.

```html
<button
  type="button"
  onClick={onSuccess}
  class="h-11 px-6 rounded-xl bg-primary text-white text-sm font-bold hover:opacity-90 transition-opacity"
>
  {t('step4Continue')}
</button>
```

Button row updated structure:
```html
<div class="flex gap-3 mt-8 justify-end items-center">
  <button type="button" onClick={onSkip} class="h-11 px-4 text-sm font-normal text-muted hover:text-text transition-colors">
    {t('step4Skip')}
  </button>
  {canAdvance && (
    <button type="button" onClick={onSuccess} class="h-11 px-6 rounded-xl bg-primary text-white text-sm font-bold hover:opacity-90 transition-opacity">
      {t('step4Continue')}
    </button>
  )}
</div>
```

Advance condition (`canAdvance`):
- At least 1 file is `status === 'ready'`
- All `ready` files have `docType` set (not undefined)
- Failed files are excluded from the check

## FileState Type Extension

Phase 3 extends the Phase 2 `FileState` type. Source: 03-CONTEXT.md code_context.

```ts
type DocType = 'da_coach' | 'template_programme';

type FileState = {
  id: string;
  file: File;
  importId?: string;
  status: 'uploading' | 'parsing' | 'ready' | 'failed';
  errorMessage?: string;
  // Phase 3 additions:
  docType?: DocType;
  clarificationPending?: boolean;
};
```

`clarificationPending` is `true` while the ambiguity pills are visible and `false` (or removed) after the coach clicks a pill. The advance condition must check `!clarificationPending` on all ready files.

## Classification Logic Contract

Source: 03-CONTEXT.md D-01, D-06, specifics.

| `overall_confidence` value | Outcome | Chat message appended |
|---------------------------|---------|----------------------|
| `null` | `docType = 'da_coach'`, no question | da_coach summary bubble |
| `< 0.4` | `docType = 'da_coach'`, no question | da_coach summary bubble |
| `>= 0.6` | `docType = 'template_programme'`, no question | template summary bubble |
| `0.4 – 0.59` (exclusive) | `clarificationPending = true` | ambiguity bubble with pills |

After ambiguity resolution (coach clicks pill):
1. `docType` set to selected value
2. `clarificationPending = false`
3. Coach reply bubble appended (right-aligned)
4. IA confirmation bubble appended

## Interaction Sequence Contract

### Happy path: high-confidence template (overall_confidence >= 0.6)

```
[polling detects status=ready]
  → classify: docType = 'template_programme'
  → setFileStates: add docType to file
  → append IA chat row: template summary bubble
  → docType badge appears on file card
  → if canAdvance: "Continuer →" button appears
```

### Happy path: low-confidence da_coach (overall_confidence < 0.4 or null)

```
[polling detects status=ready]
  → classify: docType = 'da_coach'
  → setFileStates: add docType to file
  → append IA chat row: da_coach summary bubble
  → docType badge appears on file card
  → if canAdvance: "Continuer →" button appears
```

### Ambiguity path (overall_confidence 0.4–0.59)

```
[polling detects status=ready]
  → classify: clarificationPending = true, docType = undefined
  → append IA chat row: ambiguity question bubble with pills
  → "Continuer →" does NOT appear (clarification pending)

[coach taps pill]
  → setFileStates: docType = selected, clarificationPending = false
  → pills are replaced by coach reply bubble (right-aligned, text = pill label)
  → append IA chat row: confirmation bubble ("Compris — j'ai mis à jour le type.")
  → docType badge appears on file card
  → if canAdvance: "Continuer →" button appears
```

### Multi-file: partial ready

```
File A: ready → classified → summary bubble appears immediately
File B: still parsing → no bubble
File C: failed → no bubble, no badge, does not block "Continuer →"

[File B becomes ready]
  → classified → summary bubble appended below File A's bubble
  → if all ready files have docType: "Continuer →" appears
```
