## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser client → `PUT /coach/imports/:id/commit` | Untrusted client input crosses into a write endpoint |
| polling response → component state | Server-issued `parsed_data` is retained client-side and echoed back |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Tampering | `parsed_data` echoed in the commit body | accept | The client echoes back verbatim what the server itself produced during parsing; REVIEW-02 scopes coach correction to doc TYPE only, never content, so no coach-authored data enters `parsed_data`. Server-side, `service.ts` line 385 already rejects a missing/non-object/array `parsed_data` and `db.commitImport()` `??`-guards every field access. This phase does not widen the existing surface; hardening the shape would be a Phase 28 backend change, out of scope per REQUIREMENTS.md. |
| T-04-05 | Repudiation / duplicate side-effect | double-fired commit or retry race | mitigate | Two layers. Client: `retryCommit` sets `commitStatus: 'pending'` synchronously before the fetch so the retry control disables itself; `handleConfirm` marks the whole batch pending in one update before firing. Server (authoritative): `service.ts` returns 409 before ever calling `commitImport()` a second time. `commitDoc` treats 409-with-`program_id` as success rather than trying to suppress duplicates purely client-side, since client-only prevention is bypassable. |
| T-04-06 | Elevation of Privilege | committing another coach's import | transfer | `importId` values are client-held, but `authMiddleware` + the `ai_imports_own` RLS policy enforce owner-only access server-side on every `/coach/imports/*` route. `commitDoc` forwards the caller's JWT as `Authorization: Bearer ${jwt}`; no client-side control is needed or would be sufficient. |
| T-04-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs nothing and adds no imports beyond what the file already imports. If any install appears necessary, STOP — a legitimacy gate is required and is not authorized by this plan. |
</threat_model>
