Add pipeline orchestration to WizardStep4Import.tsx. This adds two useEffect hooks and one async helper function. No JSX changes — Plan 01 already built the visual layer.

**Import to add** (if not already present from Plan 01):
- `useEffect` must be in the React import: `import { useState, useRef, useEffect } from 'react';`

**Add a ref for pipeline deduplication** (per RESEARCH.md Pitfall 4 — race condition guard):
- `const pipelineStartedRef = useRef<Set<string>>(new Set());`

This ref prevents the useEffect from triggering the pipeline twice for the same file ID. The `useEffect` fires on every `fileStates` change; without this guard, a re-render during the pipeline could trigger a duplicate `POST /coach/imports`.

**Add the pipeline function** (inside the component, after the existing helpers):

`async function runPipeline(fileState: FileState): Promise<void>` — executes the 5-step pipeline for a single file:

Step 1 — Create import record (per D-13):
- `POST ${apiUrl}/coach/imports` with body `{ filename: fileState.file.name, mime_type: fileState.file.type, size_bytes: fileState.file.size, mode: 'coach_template' }`
- Headers: `{ 'Content-Type': 'application/json', Authorization: 'Bearer ' + jwt }`
- On success (201): extract `import_id` and `signed_upload_url` from response JSON
- Update fileState: set `importId` to `import_id` (keep status as `uploading`)
- On error: set status to `failed`, set errorMessage from response text, return early

Step 2 — Upload file to signed URL (per D-13, RESEARCH Pattern 4):
- `fetch(signed_upload_url, { method: 'PUT', body: fileState.file, headers: { 'Content-Type': fileState.file.type } })`
- **CRITICAL:** Do NOT add Authorization header to signed URL — it is self-authenticating (per RESEARCH Pitfall 2)
- On error: set status to `failed`, errorMessage, return early

Step 3 — Mark as uploaded (per D-13):
- `PUT ${apiUrl}/coach/imports/${import_id}/status` with body `{ status: 'uploaded' }`
- Headers: `{ 'Content-Type': 'application/json', Authorization: 'Bearer ' + jwt }`
- On error: set status to `failed`, errorMessage, return early

Step 4 — Trigger parse (per D-13):
- `POST ${apiUrl}/coach/imports/${import_id}/parse`
- Headers: `{ Authorization: 'Bearer ' + jwt }`
- On 202 success: immediately update local fileState status to `'parsing'` (per RESEARCH Pitfall 5 — don't wait for polling to show parsing state)
- On error: set status to `failed`, errorMessage, return early

Step 5 — Start polling (per D-13, D-14):
- Call `startPolling(import_id, fileState.id)` (see below)

For ALL state updates within runPipeline, use functional updater: `setFileStates(prev => prev.map(f => f.id === fileId ? { ...f, ...changes } : f))`. Check that the file still exists in state before updating (it may have been removed via × button during the pipeline).

**Add the polling function** (per D-14, RESEARCH Polling Pattern):

`function startPolling(importId: string, fileId: string): void`:
- Creates `setInterval` with 3000ms interval
- Each tick: `GET ${apiUrl}/coach/imports/${importId}` with `Authorization: Bearer ${jwt}`
- On success: parse response as `{ import: { status: string; error_message: string | null } }`
- If status is `ready` or `failed`: clearInterval, delete from intervalsRef map, update fileState with terminal status and errorMessage (if failed)
- On fetch error: do nothing (keep polling — transient network issue)
- Store the interval handle: `intervalsRef.current.set(fileId, handle)`

**Add the pipeline trigger useEffect** (per D-12, RESEARCH Pattern 3):

```ts
useEffect(() => {
  fileStates.forEach((fs) => {
    if (fs.status === 'uploading' && !fs.importId && !pipelineStartedRef.current.has(fs.id)) {
      pipelineStartedRef.current.add(fs.id);
      runPipeline(fs);
    }
  });
}, [fileStates]);
```

This effect triggers for any new file with `status: 'uploading'` and no `importId`. The `pipelineStartedRef` guard prevents double-triggers (Pitfall 4). All files fire in parallel (D-12) — each `runPipeline` call is independent.

**Add the cleanup useEffect** (per D-14):

```ts
useEffect(() => {
  return () => {
    intervalsRef.current.forEach(clearInterval);
    intervalsRef.current.clear();
  };
}, []);
```

This cleans up ALL active polling intervals on component unmount.

**Update removeFile** (if not already done in Plan 01):
Ensure removeFile also removes the fileId from `pipelineStartedRef.current` so that if a file is removed and re-added, it gets a fresh pipeline run. Add: `pipelineStartedRef.current.delete(id);` inside removeFile.

**Do NOT:**
- Call `onSuccess` anywhere (D-17)
- Add Authorization header to the signed URL PUT (Pitfall 2)
- Use `async` in useEffect callback directly — keep the effect sync, call `runPipeline` without await (fire-and-forget per file)
- Modify any JSX structure from Plan 01

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → Hono API | JWT-authenticated POST/PUT/GET calls for import CRUD; JWT from prop |
| Client → Supabase Storage | Signed URL PUT — self-authenticating, no JWT; file bytes cross boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Spoofing | POST /coach/imports | mitigate | JWT passed via Authorization header; server validates via authMiddleware |
| T-02-05 | Tampering | Signed URL PUT body | accept | Server cannot validate file content matches declared MIME at upload time; parse step validates content downstream |
| T-02-06 | Information Disclosure | GET /coach/imports/:id | mitigate | RLS policy `ai_imports_own` ensures only owner can read import status; JWT required |
| T-02-07 | Denial of Service | Polling intervals | mitigate | Cleanup on unmount, terminal status, and file removal; 3s interval is reasonable; max 4 concurrent polls |
| T-02-08 | Elevation of Privilege | import_id in URL path | mitigate | Server-side RLS ensures user can only access their own imports; guessing IDs returns 404 |
</threat_model>
